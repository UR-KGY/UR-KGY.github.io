## 1. Spring — Bean 수동 등록 (기술 지원 빈)

공통 로그 처리처럼 여러 비즈니스 로직에서 공통으로 쓰이는 부가 기능을 **기술 지원 빈**이라고 부르고, 이런 빈은 `@Component` 자동 스캔 대신 수동으로 등록하는 경우가 많다.

- 비즈니스 로직 빈보다 수가 적어서 수동 등록 부담이 적고, 한 설정 클래스에 모아두면 "이 프로젝트에 어떤 기술 지원 빈이 있는지" 위치를 파악하기 좋다는 장점이 있다.
- 클래스에는 `@Configuration`, 메서드에는 `@Bean`을 붙여서 등록한다.

```java
@Configuration
public class SecurityConfig {

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

### PasswordEncoder 사용

`PasswordEncoder`는 인터페이스이고, `BCryptPasswordEncoder`가 그 구현체다.

```java
@Autowired
PasswordEncoder passwordEncoder;
```

이렇게 필드로 선언하면 Spring이 **반환 타입이 `PasswordEncoder`인 빈**을 찾아 주입해준다. (타입 기준 매칭).

```java
String encodedPassword = passwordEncoder.encode(password);
// 입력받은 문자열을 암호화(해시)하여 반환

boolean matches = passwordEncoder.matches(inputPassword, encodedPassword);
// (사용자가 입력한 원본 비밀번호, 저장해둔 암호화된 비밀번호) 순서로 비교하여 일치 여부를 boolean으로 반환
```


### 같은 타입의 빈이 두 개 이상일 때

```java
public interface Food {
    void eat();
}

@Component
public class Chicken implements Food {
    public void eat() { System.out.println("치킨을 먹습니다."); }
}

@Component
public class Pizza implements Food {
    public void eat() { System.out.println("피자를 먹습니다."); }
}
```

`Food` 타입 빈이 두 개 생기는 상황에서:

```java
@Autowired
Food food;  // 에러! 어떤 빈을 주입해야 할지 판단 불가 (NoUniqueBeanDefinitionException)
```

```java
@Autowired
Food pizza;
@Autowired
Food chicken;   // 필드 이름을 빈 이름과 맞춰주면 해당 빈이 주입됨
```


**`@Primary`** — 여러 후보 중 기본으로 선택될 빈을 지정.

```java
@Component
@Primary
public class Chicken implements Food { ... }

@Autowired
Food food;   // Chicken 빈이 주입됨
```

**`@Qualifier`** — 이름표를 붙여서 명시적으로 지정.

```java
@Component
@Qualifier("pizza")
public class Pizza implements Food { ... }

@Autowired
@Qualifier("pizza")
Food food;   // Qualifier 값이 "pizza"인 빈이 주입됨
```

**우선순위는 `@Qualifier` > `@Primary`**

## 2. 인증(Authentication)과 인가(Authorization)

- **인증**: 해당 사용자가 실제로 본인이 맞는지 확인하는 것 (로그인 등).
- **인가**: 인증된 사용자가 특정 자원에 접근할 **권한**이 있는지 확인하는 것 (예: 관리자 페이지 접근 가능 여부).



## 3. 쿠키(Cookie)

HTTP는 기본적으로 **비연결성(stateless)**을 가진다. 클라이언트와 서버가 요청-응답을 주고받은 뒤에는 연결을 계속 유지하지 않는데, 모든 클라이언트와의 연결을 서버가 계속 유지하려면 비용(메모리, 소켓 자원)이 커지기 때문이다. 그래서 "이 사용자가 로그인했는지" 같은 상태를 서버가 아니라 **클라이언트 쪽에 저장**하는 쿠키를 사용한다.

**쿠키의 주요 속성**

| 속성 | 의미 |
|---|---|
| Name | 쿠키를 구분하는 키 (중복 불가) |
| Value | 쿠키 값 |
| Domain | 쿠키가 저장된 도메인 |
| Path | 쿠키가 사용되는 경로 |
| Expires | 만료 기한 |

쿠키는 브라우저 개발자 도구를 열었을 때 Application(또는 저장공간) 탭에서 확인 가능하다.

### 쿠키 생성

```java
@GetMapping("/create-cookie")
public String createCookie(HttpServletResponse res) {
    addCookie("Robbie Auth", res);
    return "createCookie";
}

public static void addCookie(String cookieValue, HttpServletResponse res) {
    try {
        cookieValue = URLEncoder.encode(cookieValue, "utf-8").replaceAll("\\+", "%20");
        // 쿠키 Value에는 공백/특수문자가 허용되지 않아 URL 인코딩 진행
        Cookie cookie = new Cookie(AUTHORIZATION_HEADER, cookieValue); // Name-Value
        cookie.setPath("/");
        cookie.setMaxAge(30 * 60); // 초 단위, 30분
        res.addCookie(cookie);
    } catch (UnsupportedEncodingException e) {
        throw new RuntimeException(e.getMessage());
    }
}
```

### 쿠키 조회

```java
@GetMapping("/get-cookie")
public String getCookie(@CookieValue(AUTHORIZATION_HEADER) String value) {
    System.out.println("value = " + value);
    return "getCookie : " + value;
}
```


## 4. 웹 서버 / WAS / 톰캣 / 서블릿

```
클라이언트(브라우저) → [HTTP 요청] → 서버 → [HTTP 응답] → 클라이언트
```

- **웹 서버**: 정적 컨텐츠(이미 만들어진 HTML, 이미지, CSS 등)를 그대로 응답하는 역할.
- **WAS (Web Application Server)**: 웹 서버가 처리하지 못하는 동적 컨텐츠(DB 조회 결과, 로그인 여부에 따라 달라지는 화면 등) 처리를 담당.


- **톰캣(Tomcat)**:  "웹 서버 + WAS를 합친 것" 내부적으로 `Coyote`라는 컴포넌트가 HTTP 연결 처리(정적 컨텐츠 포함)를 담당하고, `Catalina`라는 서블릿 컨테이너가 서블릿의 생명주기를 관리하며 동적 응답을 처리한다.
- **서블릿(Servlet)**: 클라이언트의 요청을 처리하고 응답을 만들어내기 위한 자바 표준 인터페이스 또는 그 구현 클래스. 서블릿 컨테이너(톰캣의 Catalina)가 서블릿 객체의 생성·초기화·요청 처리·소멸까지 생명주기를 관리하며, 요청이 들어올 때마다 알맞은 서블릿을 실행시켜 처리를 위임한다. 
3Layer 아키텍처 의 controller 부분에 dispatcherServlet 이라는 클래스가 클라이언트의 요청을 전달한다고 한다.

## 5. Unity — Input System

유니티 6부터는 구형 InputManager 가 아닌 Input System 이 기본값이 되었다. 

### 입력값 다루기

대부분의 게임 이동 입력은 `Vector2` 타입의 Value 액션으로 받는다.

- 2D 게임: 입력값 (X, Y)를 그대로 위치/속도 계산에 사용.
- 3D 게임: Y축이 "위"인 경우가 많으므로, 입력의 (X, Y)를 `Vector3(X, 0, Y)` 형태로 매핑해서 XZ 평면상의 이동으로 사용.

`PlayerInput` 컴포넌트에 액션맵을 연결해서 쓰는 방식과, Input Actions 에셋을 "Generate C# Class"로 만들어서 코드로 직접 제어하는 방식이 있다.

아래는 PlayerInput 대신 C# 클래스로 만들어 사용하는 방식
```csharp
private void OnEnable()
{
    controller.Player.Move.performed += OnMove;
    controller.Player.Enable();
}
```


```csharp
private void OnDisable()
{
    controller.Player.Move.performed -= OnMove;
    controller.Player.Disable();
}
```

### 대각선 이동 정규화

`Vector3().normalized` 메서드를 사용하여 두 입력값의 벡터의 크기가 1이 되게 한다. 
키보드로 한 방향만 누르면 입력값이 `(1, 0)`처럼 되어 벡터의 길이도 이미 1이지만, 대각선으로 두 키를 동시에 누르면 `(1, 1)`이 되어 벡터의 길이가 `√2 ≈ 1.41`이 되어 버린다. 이 상태로 이동 속도에 곱하면 대각선으로 움직일 때 실제로 더 빨리 이동하는 버그가 생기는데, `.normalized`로 길이를 1로 맞춰주면 어느 방향으로 움직이든 이동 속도가 동일해진다. 

```csharp
Vector2 input = new Vector2(x, y);
Vector2 normalizedInput = input.normalized;  // 벡터의 길이를 1로 맞춤 
```

## 6. Unity — 코루틴(Coroutine)

- `Update()`와 별개로, 프레임 단위 또는 시간 단위로 코드를 실행할 수 있다.
- `StartCoroutine()`에 넣어 실행하며, 첫 `yield` 문을 만나기 전까지는 일반 함수처럼 그 자리에서 즉시 실행된다.
- `yield return`을 만나면 유니티 엔진에 제어권을 반환하고 대기하며, 재개 시점은 `yield` 뒤에 오는 명령에 따라 다르다 
- 종료 시점: 함수 끝에 도달, `yield break;` 사용, `StopCoroutine()`(코루틴 참조 변수 또는 이름 문자열로), `StopAllCoroutines()`, 그리고 오브젝트가 파괴되거나 비활성화될 때도 자동으로 종료된다.

|yield 명령문|	재개(다시 실행) 시점|
|---|---|
|yield return null;|	다음 프레임에 재개|
|yield return new WaitForSeconds(n);|	게임 시간 기준 n초 후 재개 (Time.timeScale 영향 받음)|
|yield return new WaitForSecondsRealtime(n);|	실제 시간 기준 n초 후 재개 (Time.timeScale 영향 안 받음, 일시정지 중에도 흐름)|
|yield return new WaitForFixedUpdate();	|다음 FixedUpdate 직전에 재개 (물리 연산 타이밍에 맞춤)|
|yield return new WaitForEndOfFrame();	|해당 프레임의 렌더링까지 모두 끝난 직후 재개|
|yield return new WaitUntil(() => 조건);|	조건식이 true가 될 때까지 매 프레임 검사 후 재개|
|yield return new WaitWhile(() => 조건);|	조건식이 false가 될 때까지 매 프레임 검사 후 재개 (WaitUntil의 반대)|
|yield return StartCoroutine(다른코루틴());|	그 안에서 호출한 다른 코루틴이 완전히 끝난 뒤 재개 (코루틴 중첩/순차 실행)|
|yield return www; / yield return asyncOp;|	네트워크 요청이나 비동기 작업(UnityWebRequest, AsyncOperation 등)이 끝난 뒤 재개|
|yield break;|	재개 없음 — 그 자리에서 코루틴 즉시 종료|


## 7. Unity — JSON 직렬화/역직렬화

```csharp
[Serializable]
public class UserData
{
    public List<User> users = new List<User>();
}

[Serializable]
public class User
{
    public string name;
    public int age;
    public int score;
}

public class DataManager : MonoBehaviour
{
    [SerializeField]
    private UserData data = new UserData();
    string path;

    void Start()
    {
        path = Application.persistentDataPath + "/Data.json";
        Debug.Log(Application.persistentDataPath);
        SaveToJson();
    }

    private void SaveToJson()
    {
        string json = JsonUtility.ToJson(data);
        File.WriteAllText(path, json);
        Debug.Log(json);
    }

    private void LoadFromJson()
    {
        string json = File.ReadAllText(path);
        data = JsonUtility.FromJson<UserData>(json);
    }
}
```

- `Application.persistentDataPath`: 플랫폼마다 앱이 자유롭게 읽고 쓸 수 있는 경로 (Windows에서는 `AppData/LocalLow/회사이름/프로젝트이름`)

오브젝트 생성 시점에 `Application.persistentDataPath` 를 불러오면 오류가 발생하여 awake() 나 start() 시점에 초기화

```csharp
string path = Application.persistentDataPath + "/Data.json";  // 필드 선언과 동시에 초기화 → 문제 발생 가능
```
