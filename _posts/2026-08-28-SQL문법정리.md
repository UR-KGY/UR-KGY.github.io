# SQL 문법 정리

지금까지 MANAGER/STUDENT/EXAM 테이블로 실습하면서 나온 문법들을 예시 중심으로 정리한다. 크게 **DDL(구조 정의)**, **DML(데이터 조작)**, **JOIN(조회 연결)** 세 덩어리로 나뉜다.

## 1. DDL — 테이블 구조 정의

### CREATE TABLE + 제약조건

```sql
CREATE TABLE IF NOT EXISTS MANAGER (
    id           BIGINT       NOT NULL AUTO_INCREMENT,
    name         VARCHAR(10)  NOT NULL,
    student_code VARCHAR(100) NOT NULL,
    PRIMARY KEY (id),
    CONSTRAINT manager_fk_student_code
        FOREIGN KEY (student_code) REFERENCES student(student_code)
        ON DELETE CASCADE,
    CHECK (CHAR_LENGTH(name) >= 2)
);
```

| 키워드 | 역할 | 예시 |
|---|---|---|
| `PRIMARY KEY` | 행을 유일하게 식별하는 값 | `id BIGINT PRIMARY KEY` |
| `NOT NULL` | 빈 값(NULL) 저장 금지 | `name VARCHAR(10) NOT NULL` |
| `AUTO_INCREMENT` | INSERT 시 값을 자동으로 1씩 증가시켜 채움 | `id BIGINT AUTO_INCREMENT` — PK/UNIQUE 등 인덱스가 걸린 컬럼에만 가능 |
| `FOREIGN KEY` | 다른 테이블의 값만 참조하도록 강제 | `FOREIGN KEY (student_code) REFERENCES student(student_code)` |
| `CONSTRAINT 이름` | 제약조건에 직접 이름 부여(안 하면 자동 생성됨) | `CONSTRAINT manager_fk_student_code FOREIGN KEY (...)` |
| `CHECK` | 값의 조건(범위, 길이 등)을 검증 | `CHECK (CHAR_LENGTH(name) >= 2)` — MySQL 8.0.16 이상에서 실제로 강제됨 |
| `ON DELETE CASCADE` | 참조 대상(부모) 행이 삭제되면 자식 행도 자동 삭제 | STUDENT의 s1 삭제 → MANAGER/EXAM의 s1 행도 자동 삭제 |
| `COMMENT` | 데이터 검증과 무관한 설명(문서화용) | `name VARCHAR(10) COMMENT '이름'` |

### ALTER TABLE — 이미 만든 테이블 구조 바꾸기

`MODIFY COLUMN`은 **그 컬럼 자체의 정의(타입·NOT NULL·DEFAULT·AUTO_INCREMENT·COMMENT)를 통째로 덮어쓴다.** 기존 값을 유지하고 싶은 속성도 전부 다시 써줘야 한다. 단, `PRIMARY KEY`·`FOREIGN KEY`·`CHECK`처럼 테이블 레벨에 별도로 걸린 제약조건은 컬럼 정의에 포함되지 않으므로 다시 쓸 필요 없다(오히려 PK를 또 쓰면 `Multiple primary key defined` 에러가 남).

```sql
-- 컬럼 타입/속성 변경 (기존 NOT NULL도 같이 다시 써야 유지됨)
ALTER TABLE manager MODIFY id BIGINT NOT NULL AUTO_INCREMENT;

-- 컬럼에 COMMENT 추가 (기존 정의를 그대로 유지하며 COMMENT만 덧붙임)
ALTER TABLE manager MODIFY COLUMN name VARCHAR(10) NOT NULL COMMENT '매니저 이름';

-- 테이블 전체 COMMENT (컬럼과 달리 이건 속성 하나만 targeted하게 바꿀 수 있음)
ALTER TABLE manager COMMENT = '매니저 정보 테이블';
```

FK의 `ON DELETE` 옵션은 `MODIFY`로 바로 못 바꾼다. **기존 FK를 DROP하고 CASCADE 옵션을 붙여 다시 ADD**해야 한다.

```sql
ALTER TABLE manager
    DROP FOREIGN KEY manager_fk_student_code,
    ADD CONSTRAINT manager_fk_student_code
        FOREIGN KEY (student_code) REFERENCES student(student_code)
        ON DELETE CASCADE;
```

컬럼 추가/삭제, 테이블 삭제:

```sql
ALTER TABLE manager ADD COLUMN memo VARCHAR(50);   -- 컬럼 추가
ALTER TABLE manager DROP COLUMN memo;              -- 컬럼 삭제
DROP TABLE manager;                                -- 테이블 자체 삭제
```

구조 확인은 `ALTER`가 아니라 **조회 명령**으로 먼저 한다(구조를 바꾸지 않고 읽기만 함).

```sql
DESC manager;                 -- 컬럼 목록 간단히
SHOW CREATE TABLE manager;    -- CREATE TABLE 문 전체(제약조건 이름 포함)
```

## 2. DML — 데이터 자체를 다루기

```sql
-- 여러 행을 한 번에 삽입 (id는 AUTO_INCREMENT라 생략)
INSERT INTO manager (name, student_code) VALUES
('managerA', 's1'),
('managerA', 's2'),
('managerB', 's6');

-- 조건에 맞는 행만 값 수정
UPDATE manager SET name = 'managerC' WHERE student_code = 's1';

-- 조건에 맞는 행 삭제 (FK에 CASCADE가 걸려있으면 자식 테이블도 같이 삭제됨)
DELETE FROM student WHERE student_code = 's1';
```

### SELECT 조회를 다듬는 절

```sql
SELECT name, student_code
FROM manager
WHERE name = 'managerA'      -- 조건 필터링
ORDER BY student_code ASC    -- 정렬
LIMIT 5;                     -- 개수 제한
```

컬럼/테이블에 별칭(AS)을 붙일 땐 **점(`.`) 없이** 붙인다. 점은 별칭을 "정의"할 때가 아니라, 정의된 별칭으로 컬럼을 "가리킬 때"만 쓴다.

```sql
SELECT m.name AS '매니저 이름'   -- 컬럼 별칭
FROM manager m;                 -- 테이블 별칭 (m.으로 나중에 참조 가능해짐)
```

## 3. JOIN — 여러 테이블을 연결해서 조회

| 종류 | 의미 | 예시 |
|---|---|---|
| `INNER JOIN` (그냥 `JOIN`) | 양쪽 다 매칭되는 행만 | `manager m JOIN student s ON m.student_code = s.student_code` |
| `LEFT JOIN` | FROM(왼쪽) 테이블은 전부 살리고, 안 맞으면 오른쪽은 NULL | `student s LEFT JOIN manager m ON ...` → 매니저 없는 학생도 다 나옴 |
| `RIGHT JOIN` | LEFT JOIN의 반대. `A RIGHT JOIN B` = `B LEFT JOIN A` | 실무에선 잘 안 쓰고 LEFT JOIN으로 통일하는 경우가 많음 |

**3개 이상 테이블 연결**은 JOIN을 계속 이어붙이면 된다. 중간 테이블은 연결(다리) 역할만 하고 SELECT에 안 나올 수도 있다.

```sql
SELECT s.name AS '학생이름', e.exam_seq AS '시험 주차', e.score AS '점수'
FROM student s
JOIN manager m ON m.student_code = s.student_code
JOIN exam e ON s.student_code = e.student_code
WHERE m.name = 'managerA';   -- JOIN은 "연결"만, "필터링"은 WHERE가 담당
```

- **INNER JOIN**끼리는 테이블을 적는 순서를 바꿔도 결과가 같다.
- **LEFT/RIGHT JOIN**은 순서가 결과 자체를 바꾼다(어느 쪽을 다 살릴지가 정해짐).
- `SELECT *`일 때 컬럼이 나열되는 순서는 "어느 테이블이 살아남는지"와 무관하고, 그냥 `FROM`/`JOIN`에 테이블을 적은 순서를 따른다.

## 한 줄 정리

- 테이블/컬럼의 **구조**를 정의·변경하는 건 `CREATE`/`ALTER`/`DROP`(DDL), **데이터 값** 자체를 다루는 건 `INSERT`/`UPDATE`/`DELETE`/`SELECT`(DML) — 이 둘을 헷갈리면 안 된다(COMMENT를 `UPDATE`로 고치려던 실수가 이 경우).
- `CONSTRAINT 이름`은 규칙의 동작에는 영향 없지만, 에러 메시지·삭제·유지보수 편의성 때문에 실무에서 꼭 지정한다.
- `MODIFY COLUMN`은 컬럼 정의를 통째로 덮어쓰므로 유지하고 싶은 속성도 다시 써야 하지만, PK/FK/CHECK 같은 테이블 레벨 제약조건은 안 건드려도 유지된다.
- FK의 `ON DELETE CASCADE`는 MODIFY로 못 바꾸고, DROP 후 재생성해야 한다.
- JOIN은 "연결", WHERE는 "그중에서 골라내기" — 역할이 다르다. LEFT/RIGHT JOIN은 순서가 결과를 바꾸지만 INNER JOIN은 안 바뀐다.
