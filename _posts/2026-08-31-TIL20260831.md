## 1. URL 구조
 
| 명칭 | 구조 예시 | 역할 |
|---|---|---|
| scheme | `https` | 사용할 통신 방식(프로토콜) |
| host | `www.naver.com` | 접속할 서버 이름(도메인) |
| port | `443` | 서버 안에서 어떤 서비스로 연결할지 구분하는 번호 |
| path | `/product/423` | 요청할 자원(페이지, 데이터 등)의 위치 |
| query | `color=blue&sort=price` | 서버에 전달할 추가 조건(옵션) |
| fragment | `review` | 받은 문서 안에서 이동할 위치 (서버로 전달되지 않고 브라우저 안에서만 쓰임) |
 
 예시
```
https://www.naver.com:443/product/423?color=blue&sort=price#review
```
 
https는 기본 포트가 443이라 실제로는 포트 번호를 생략하고 `https://www.naver.com/product/423`처럼 쓰는 경우가 대부분이다.
 
## 2. DNS
 
**DNS(Domain Name System)**는 `www.naver.com` 같은 도메인 이름(사람이 외우기 쉬운 이름)을 실제 서버 위치인 **IP 주소**(예: `123.45.67.89`, 컴퓨터가 인식하는 숫자 주소)로 바꿔주는 서비스
 
## 3. HTTP vs HTTPS
 
| 구분 | http | https |
|---|---|---|
| 정의 | 웹에서 데이터를 주고받는 통신 규칙 | TLS(암호화 기술)로 보호된 http |
| 암호화 | 없음 | 있음 |
| 서버 신원 확인 | 없음 | 인증서로 서버를 확인함 |
| 기본 포트 | 80 | 443 |
 
## 4. Git 명령어
 
| 명령어 | 하는 일 |
|---|---|
| `git init` | 현재 폴더를 Git 저장소로 새로 초기화함 (`.git` 폴더 생성, 폴더당 한 번만 하면 됨) |
| `git branch` | 로컬에 있는 브랜치 목록을 보여줌 (현재 브랜치 앞에 `*` 표시) |
| `git branch '이름'` | `'이름'`으로 브랜치를 생성만 함 (이동은 안 됨) |
| `git checkout '이름'` / `git switch '이름'` | 그 브랜치로 이동함 |
| `git checkout -b '이름'` | 브랜치 생성과 이동을 한 번에 |
| `git add .` | 변경된 내용을 커밋 대상으로 스테이징(임시 등록)함 |
| `git commit -m '메시지'` | 스테이징된 내용을 로컬 저장소에 저장함 (아직 원격엔 반영 안 됨) |
| `git commit -am '메시지'` | add + commit을 한 번에. 단, 이미 Git이 추적 중인 파일의 수정사항만 자동 반영됨 (새로 만든 파일은 별도로 `add` 필요) |
| `git push` | 로컬 커밋을 연결된 GitHub 저장소에 반영 (최초 1회는 `git push -u origin 브랜치명`으로 연결 필요) |
| `git pull` | GitHub 저장소의 변경사항을 현재 폴더로 가져와 반영 |
| `git clone '주소'` | `'주소'`의 GitHub 저장소를 현재 위치에 통째로 복제해옴 |
| `git status` | 지금 어떤 파일이 바뀌었는지, 스테이징됐는지 확인 (자주 쓰면 실수 방지에 좋음) |

## 6. 기본 타입 vs 참조 타입
 
- **기본 타입(primitive type)**: `boolean`, `char`, `byte`, `int` 등 자바가 기본으로 제공하는 타입. 비교 연산자(`==`)를 쓰면 값 자체를 비교함.
- **참조 타입(reference type)**: `Class`, 배열, 인터페이스 등. 변수(스택에 저장됨)가 실제 객체(힙에 저장됨)의 주소를 참조한다고 해서 참조 타입이라고 부름. `==`를 쓰면 같은 객체(주소)인지를 비교함. 내용이 같은지 비교하고 싶을 땐 `==`가 아니라 `.equals()`를 써야 함 
```java
String a = new String("hi");
String b = new String("hi");
a == b        // false (서로 다른 객체 주소)
a.equals(b)   // true (내용은 같음)
```
 
- **래퍼 타입(wrapper type)**: 기본 타입을 감싸서 객체(참조 타입)로 만든 것. 예: `int` → `Integer`, `boolean` → `Boolean`. `List`나 `Map` 같은 자료구조는 기본 타입을 직접 담을 수 없게 설계되어 있어서, 기본 타입을 담으려면 반드시 래퍼 타입으로 감싸야 함. 문자열↔숫자 변환(`Integer.parseInt()` 같은) 기능도 제공
## 7. 자료구조
 
- 자바의 자료구조(`List`, `Map`, `Set` 등)에는 기본 타입을 직접 넣을 수 없어요. 기본 타입이 필요하면 래퍼 클래스로 대체해서 넣어요. (예: `List<int>`는 불가능, `List<Integer>`는 가능)
- `Set`은 중복을 허용하지 않음.
- 시간복잡도는 구현체에 따라 달라요.
  - `HashMap`, `HashSet`: 평균적으로 O(1) (데이터가 많이 몰리는 최악의 경우엔 느려질 수 있음)
- 자바에서 자주 쓰는 자료구조: `ArrayList<>`, `HashMap<>`, `HashSet<>` (기준은 평균 O(1)인 HashMap, HashSet)
