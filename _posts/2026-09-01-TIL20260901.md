# 2026-09-01 TIL

## 1. 반복문 — 향상된 for문 (foreach)

자바에선 자료구조를 순회하기 위해 향상된 for 문을 사용한다. (C#에서의 foreach와 기능이 동일)

**Java**
```java
List<Hero> party = new ArrayList<>();

for (Hero hero : party) {
    // hero 사용
}
```

**C#**
```csharp
List<Hero> party = new List<Hero>();

foreach (Hero hero in party)
{
    // hero 사용
}
```
- 자바는 `:` 로 연결, C#은 `in` 이라는 키워드로 연결한다는 문법 차이만 있고 동작은 동일하다.
- 인덱스(순번) 관리 없이 요소를 하나씩 꺼낼 수 있다는 목적도 동일하다.

## 2. Enum

Enum은 Java 와 C# 형식이 각각 다르게 표현된다

###

| | Java | C# |
|---|---|---|
| 정체 | 특수한 **클래스** (각 항목이 인스턴스/객체) | 이름표가 붙은 **정수 값 형식(value type)** |
| 저장 위치 | 참조 타입 → 힙(heap) | 값 형식 |
| 생성자/필드/메서드 | 가능 | 기본 문법으로는 불가능 |

### 기본 사용 — 문자열 대체 + switch

Enum은 문자열로 상태를 표현하는 것을 대체해 오타를 방지하고, switch-case 같은 조건 분기에 자주 쓰인다는 점은 두 언어가 동일하다.

```csharp
public enum PlayerState
{
    Idle,       // = 0
    Walking,    // = 1
    Jumping,    // = 2
    Attacking,  // = 3
    Dead        // = 4
}
```

C#은 값을 지정 안 하면 0부터 자동으로 매겨지는데, 이 숫자는 평소엔 안 보이고 이름으로만 다뤄진다.

```csharp
Debug.Log(PlayerState.Idle);        // "Idle"  (자동으로 ToString() 호출됨)
Debug.Log((int)PlayerState.Idle);   // 0       (캐스팅해야 진짜 숫자가 보임)
```

`Idle` 이라는 이름이 가리키는 값 자체는 고정 상수이지만, Enum **변수**는 다른 값으로 재할당 가능하다 (읽기 전용인 건 "각 항목의 값"이지 "변수"가 아님).

### 값 직접 지정하기 (Java, C# 공통)

```csharp
public enum ItemRarity
{
    Common = 1,
    Rare = 5,
    Epic = 10,
    Legendary = 20
}
```

외부 데이터(기획서, DB)의 ID와 맞추거나, 나중에 항목을 끼워 넣을 여유 공간을 만들 때 사용.

### 항목마다 필드를 주입하는 Enum — Java만 기본 지원

**Java (가능)**
```java
public enum Menu {
    AMERICANO("아메리카노", 4500),
    LATTE("라떼", 5000),
    GREEN_TEA("녹차", 4000);

    private final String displayName;
    private final int price;

    Menu(String displayName, int price) {
        this.displayName = displayName;
        this.price = price;
    }

    public String getDisplayName() { return displayName; }
    public int getPrice() { return price; }
}

System.out.println(Menu.AMERICANO.getPrice());  // 4500
```

Java의 enum은 클래스이기 때문에 생성자로 항목마다 다른 필드 값을 주입할 수 있다.

## 3. Set (HashSet)

`List`와 달리 **중복을 허용하지 않고**, **순서를 보장하지 않는** 자료구조다. 

```csharp
using System.Collections.Generic;

HashSet<string> visitedRooms = new HashSet<string>();
visitedRooms.Add("던전1");
visitedRooms.Add("던전1");           // 중복 → 무시됨

bool has = visitedRooms.Contains("던전1");  // true, List보다 빠르게 확인 가능
visitedRooms.Remove("던전2");
```

## 4. Generic과 박싱/언박싱

자바에서 Generic 을 사용할 때는 모든 클래스들이 상속하고 있는 Object 로 타입을 형변환하여 사용하기 때문에 기본 타입(값 타입) 이 들어가지 않는다.(따라서 래퍼 클래스 이용) 
C#은 Generic을 사용할 때 기본 타입도 들어간다. 

| | Java | C# |
|---|---|---|
| 동작 방식 | 타입 소거(type erasure) — 내부적으로 전부 `Object`로 취급 | 구체화(reification) — 타입별 전용 코드 생성 |
| `int` 같은 기본 타입 | Generic에 직접 불가 → **래퍼 클래스**(`Integer` 등) 필요 | `List<int>` 처럼 값 형식도 **바로 사용 가능** |
| 성능 | 래퍼 클래스 사용 시 박싱 발생 | 박싱 없이 동작 (더 효율적) |

```java
// Java
List<Integer> scores = new ArrayList<>();  // int가 아니라 Integer(래퍼 클래스)
```

```csharp
// C#
List<int> scores = new List<int>();  // int를 그대로 사용, 박싱 없음
```

### 박싱(Boxing) / 언박싱(Unboxing)이란

- **박싱**: `int`, `double`, `bool`, `struct` 같은 값 형식을 `object`로 취급할 때, 힙(heap)에 새 객체를 만들어 값을 복사해 넣는 과정.
- **언박싱**: 반대로 `object`에서 값 형식을 다시 꺼내는 과정.
- 문제점: 힙에 만들어진 박싱 객체들이 가비지 컬렉션 대상이 되고, 이게 자주 발생하면 순간적인 프리징(스터터링) 현상으로 이어질 수 있다.

**C#에서 박싱이 일어나는 대표 상황**

```csharp
object obj = 5;                       // 값 형식 → object 대입
ArrayList list = new ArrayList();
list.Add(5);                          // 비-제네릭 컬렉션에 값 형식 추가

interface IShape { void Draw(); }
struct Circle : IShape { public void Draw() {} }
IShape shape = new Circle();          // 구조체를 인터페이스 타입으로 다룰 때
```

**Java에서 박싱/언박싱이 일어나는 대표 상황**

```java
List<Integer> scores = new ArrayList<>();
scores.add(100);              // 오토박싱 (int → Integer)

Integer a = 100;
int b = a + 5;                 // 오토언박싱 (Integer → int)

Integer x = 200, y = 200;
System.out.println(x == y);    // false — 참조 비교 함정, equals() 써야 함

Integer count = null;
int n = count;                  // NullPointerException — null 언박싱 불가
```

**조심해야 할 타이밍**: 유니티의 `Update()`처럼 매 프레임 반복 실행되는 코드(핫패스)에서 박싱이 일어나면 매번 쓰레기 객체가 쌓여 성능 저하로 직결된다. 제네릭 컬렉션(`List<T>`) 사용, 구조체를 인터페이스로 감싸지 않기 등으로 예방.

## 5. 예외 처리

### Checked vs Unchecked — 가장 큰 철학 차이

| | Java | C# |
|---|---|---|
| Checked Exception | 있음 (`IOException` 등, `throws` 선언 강제, 안 하면 컴파일 에러) | **없음** — 모든 예외가 unchecked |
| Unchecked Exception | 있음 (`NullPointerException` 등) | 전체가 이 방식 |

C#은 어떤 예외가 날 수 있는지 컴파일러가 강제하지 않으므로, 문서를 보고 개발자가 판단해 필요한 곳에 `try-catch`를 넣는다.

### 자원 자동 정리

```java
// Java — try-with-resources, AutoCloseable 인터페이스 기반
try (FileReader reader = new FileReader("file.txt")) {
    // 사용
}
```

```csharp
// C# — using, IDisposable 인터페이스 기반
using (var reader = new StreamReader("file.txt"))
{
    // 사용
}
```

### C#에만 있는 예외 필터

```csharp
catch (Exception e) when (e.Message.Contains("network"))
{
    // 조건까지 만족할 때만 처리
}
```

### 대표적으로 자주 만나는 예외 (Java → C# 대응)

| Java | C# | 발생 상황 |
|---|---|---|
| `NullPointerException` | `NullReferenceException` | null 객체의 멤버 접근 |
| `ArrayIndexOutOfBoundsException` | `IndexOutOfRangeException` | 배열 범위 초과 |
| `ClassCastException` | `InvalidCastException` | 잘못된 형변환 |
| `NumberFormatException` | `FormatException` | 숫자로 파싱 불가한 문자열 |
| `ArithmeticException` | `DivideByZeroException` | 정수를 0으로 나눔 |
| `IllegalArgumentException` | `ArgumentException` | 유효하지 않은 인자 전달 |
| `ConcurrentModificationException` | `InvalidOperationException` | foreach 순회 중 컬렉션 수정 |
| `StackOverflowError` | `StackOverflowException` | 무한 재귀 (C#에서는 catch 불가) |
| `UnsupportedOperationException` | (해당 없음, 주로 직접 예외 정의) | 읽기 전용 컬렉션 수정 시도 |


### Optional — null을 통제하기 위한 자료형 (Java)

```java
Optional<Hero> optionalHero = Optional.ofNullable(item);

Hero hero = optionalHero.orElseThrow();
// 인자 없이 쓰면 기본으로 NoSuchElementException 던짐

Hero hero2 = Optional.ofNullable(item)
    .orElseThrow(() -> new IllegalArgumentException("아이템이 존재하지 않습니다"));
// 원하는 예외를 직접 지정해서 던지는 것도 가능
```

- `orElse(기본값)` — 없으면 기본값
- `orElseGet(() -> ...)` — 없으면 함수 실행 결과
- `isPresent()` / `ifPresent(...)` — 존재 여부 확인

## 6. Stream (Java) vs LINQ (C#)

컬렉션 데이터를 반복문 없이 "가공 파이프라인" 형태로 처리하는 기능. 

```java
// Java Stream
List<String> aliveHeroNames = party.stream()
    .filter(h -> h.getHp() > 0)     // 조건에 맞는 것만 남기기
    .map(h -> h.getName())          // 변환
    .collect(Collectors.toList());  // 최종 결과로 모으기
```

```csharp
// C# LINQ
List<string> aliveHeroNames = party
    .Where(h => h.Hp > 0)   // filter에 해당
    .Select(h => h.Name)    // map에 해당
    .ToList();               // collect(toList())에 해당
```

### 대응표

| Java Stream | C# LINQ | 역할 |
|---|---|---|
| `filter()` | `Where()` | 조건에 맞는 것만 남기기 |
| `map()` | `Select()` | 각 요소 변환 |
| `sorted()` | `OrderBy()` | 정렬 |
| `distinct()` | `Distinct()` | 중복 제거 |
| `collect(toList())` | `ToList()` | 결과를 리스트로 |
| `findFirst()` | `First()` / `FirstOrDefault()` | 걸러낸 것 중 첫 번째 반환 |
| `anyMatch()` | `Any()` | 조건 만족하는 게 하나라도 있는지 |
| `count()` | `Count()` | 개수 세기 |
