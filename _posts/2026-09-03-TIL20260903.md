# 유니티 캐릭터 이동 · 카메라 
내일부터 본격적으로 스프링을 사용하여 과제를 수행할 것 같다. 
우선적으로는 스프링을 배우고 나머지 시간을 유니티 쪽에 집중해야할 것 같다. 

## 1. Rigidbody vs CharacterController

| 구분 | Rigidbody | CharacterController |
|---|---|---|
| 이동 원리 | 물리 엔진이 힘/속도를 계산해서 이동시킴 | 넘겨준 벡터만큼 직접 이동, 물리 계산 없음 |
| 호출 위치 | `FixedUpdate()` | `Update()` |
| 수평 이동 방법 | `linearVelocity` 대입 (또는 `AddForce`) | `Move(Vector3 motion)`에 방향×속도×`Time.deltaTime` |
| 중력 | 자동 적용 (`useGravity`) | 없음 — 직접 변수로 누적 계산해야 함 |
| 접지 판정 | 내장 없음 — Raycast/Trigger로 직접 구현 | `isGrounded` 프로퍼티 내장 |
| 점프 구현 | `AddForce(.., ForceMode.Impulse)`로 순간적인 힘 | 힘 개념 없음 — `verticalVelocity`를 직접 세팅해서 Move의 이동량에 합산 |
| 경사/계단 처리 | 물리적으로 계산되지만 어색할 수 있음 | Slope Limit/Step Offset으로 자연스럽게 처리 |
| 다른 물체와 상호작용 | 충돌 시 서로 밀림(반작용) 자연스러움 | 기본적으로 다른 물체를 밀지 못함(별도 로직 필요) |
| 회전 안정성 | 콜라이더 충돌로 넘어질 수 있음 (Constraints로 방지) | 캡슐이 항상 세워진 채로 유지됨 |
| 적합한 상황 | 넉백, 폭발, 밀림 등 사실적 물리 반응 | 예측 가능한 사람 캐릭터 조작 |

Unity 6부터 `Rigidbody.velocity` → `linearVelocity`, `Drag` → `Linear Damping`으로 이름이 바뀌었다.

## 2. Rigidbody 기반 이동

### 2.1 MovePosition의 함정

`rb.MovePosition(position)`은 "이 방향으로 움직여라"가 아니라 **"이 절대 좌표로 이동시켜라"**는 의미다. 방향 벡터를 그대로 넘기면, 입력이 들어올 때마다 원점 근처의 고정된 한 점으로 순간이동하게 된다. (캐릭터가 (0,0,0)에 있고 입력값이 (1,0,0)이면 그 좌표로 튀어버리고, 입력이 (0,0,0)으로 돌아오면 다시 원점으로 롤백되는 것처럼 보였던 현상의 원인.)

올바른 계산은 **현재 위치 + 이동량**이다.

```csharp
Vector3 direction = new Vector3(moveInput.x, 0, moveInput.y).normalized;
Vector3 target = rb.position + direction * speed * Time.deltaTime;
rb.MovePosition(target);
```

### 2.2 velocity로 전환한 이유

MovePosition은 목표 y값을 "지금 위치 그대로"로 강제하기 때문에, 중력이나 점프로 만들어지는 y축 움직임과 계속 충돌한다. 그래서 수평 이동은 위치가 아니라 **속도(velocity)를 직접 지정**하는 방식으로 바꾼다. y값(중력·점프)은 건드리지 않고 x/z만 갈아끼운다.

```csharp
Vector3 direction = new Vector3(moveInput.x, 0, moveInput.y).normalized;
Vector3 v = rb.linearVelocity;
rb.linearVelocity = new Vector3(direction.x * speed, v.y, direction.z * speed);
```

velocity는 "초당 이동 거리"라는 비율이라, 물리 엔진이 매 물리 스텝마다 알아서 `velocity × Time.fixedDeltaTime`을 계산해 위치를 갱신해준다. 그래서 velocity 대입에는 `Time.deltaTime`을 곱할 필요가 없다. 반면 MovePosition·CharacterController.Move()는 "이번 프레임에 이동할 거리" 자체를 받기 때문에, `speed(초당 거리) × Time.deltaTime(이번 프레임 시간)`으로 직접 거리를 계산해서 넘겨야 한다.

### 2.3 점프와 접지 판정

```csharp
private void Jump()
{
    if (Physics.Raycast(rb.position, Vector3.down, checkDistance, groundLayer))
    {
        rb.AddForce(new Vector3(0, 3, 0) * jumpPower, ForceMode.Impulse);
    }
}
```

`Physics.Raycast(origin, direction, layerMask)`처럼 3개 인자만 넘기면, 세 번째 값이 `layerMask`가 아니라 `maxDistance`(float) 자리에 들어간다. `LayerMask → int → float` 암묵적 변환이 되기 때문에 컴파일은 되지만 레이어 필터링이 전혀 적용되지 않는 버그가 생긴다. 
### 2.4 그 외 캐릭터용 Rigidbody 설정

- **Constraints (Freeze Rotation X, Z)** — 충돌로 캐릭터가 넘어지는 것 방지 (Y축 회전은 열어둠)
- **Collision Detection: Continuous** — 빠르게 움직이는 캐릭터가 얇은 벽을 뚫고 지나가는 것 방지
- **Interpolate** — 물리 스텝(FixedUpdate)과 렌더 프레임 속도 차이로 생기는 미세한 떨림을 보간해 부드럽게 보정

## 3. CharacterController 기반 이동

```csharp
public class CharacterControllerPlayerMovement : PlayerMovement
{
    CharacterController characterController;
    [SerializeField] private float gravity = -9.8f;
    private bool isJumpPressed = false;
    private float verticalVelocity;

    protected override void Awake()
    {
        base.Awake();
        characterController = GetComponent<CharacterController>();
    }

    protected override void Update()
    {
        Move();
    }

    private void Move()
    {
        bool isGrounded = characterController.isGrounded;

        // 보완: 접지 상태에서 velocity가 무한정 음수로 쌓이는 것 방지
        if (isGrounded && verticalVelocity < 0)
        {
            verticalVelocity = -2f;
        }

        if (isGrounded && isJumpPressed)
        {
            verticalVelocity = jumpPower;
            isJumpPressed = false;
        }

        verticalVelocity += gravity * Time.deltaTime;

        Vector3 direction = new Vector3(moveInput.x, 0, moveInput.y).normalized;
        Vector3 motion = (direction * speed + Vector3.up * verticalVelocity) * Time.deltaTime;
        characterController.Move(motion);
    }

    protected override void Jump()
    {
        if (!characterController.isGrounded) return;
        isJumpPressed = true;
    }
}
```
### 
- CharacterController는 중력이 자동 적용되지 않으므로 `verticalVelocity`를 직접 변수로 들고 매 프레임 `gravity * Time.deltaTime`만큼 누적해야 한다.
- 점프는 `AddForce` 같은 힘 개념이 없다. 그냥 그 순간 `verticalVelocity`를 원하는 값으로 **대입**하면 되고, 이후엔 매 프레임 도는 중력 누적 로직이 자연스럽게 감속 → 정점 → 낙하까지 다 처리해준다. 별도의 코루틴이나 Lerp로 "일정 시간 유지 후 전환"하는 방식은 오히려 부자연스러운 궤적(포물선이 아니라 뚝 끊기는 움직임)을 만든다.
- `isGrounded`는 내장 프로퍼티라 별도 Raycast가 필요 없다.

## 4. 카메라가 플레이어를 따라가게 만들기

### 4.1 스크립트로 직접 구현

```csharp
public class FollowingPlayer : MonoBehaviour
{
    private Transform player;
    private float distance_y = 1;
    private float distance_z = -10;
    [SerializeField] private float smoothTime; // followSpeed보다 의미가 정확한 이름
    private Vector3 currentVelocity;

    void Start()
    {
        player = FindFirstObjectByType<Player>().transform;
    }

    private void LateUpdate()
    {
        Follow();
    }

    private void Follow()
    {
        Vector3 targetPosition = new Vector3(player.position.x, player.position.y + distance_y, player.position.z + distance_z);
        transform.position = Vector3.SmoothDamp(transform.position, targetPosition, ref currentVelocity, smoothTime);
    }
}
```

- **LateUpdate에서 처리하는 이유**: 플레이어 이동이 다 끝난 뒤(그 프레임의 최종 위치 기준)에 카메라를 갱신해야 한 프레임 지연되는 걸 방지할 수 있다.
- **Vector3.Lerp(a, b, t)**: 두 점 사이를 `t`(0~1) 비율로 보간하는 단순 계산. 매 프레임 반복 호출하면 "남은 거리의 일정 비율만큼씩" 좁혀가는 방식이라 결과적으로 감쇠 곡선이 나오지만, 정확한 도착 시간을 지정하긴 어렵다.
- **Vector3.SmoothDamp(current, target, ref velocity, smoothTime)**: 현재 속도를 계속 추적해서 관성 있는 자연스러운 가속/감속을 만들어준다. `smoothTime`으로 "대략 몇 초 안에 도착할지"를 직접 지정할 수 있어 카메라 추적에 더 적합하다. `ref velocity`는 클래스 필드로 선언해서 프레임 간 유지되어야 하며, 초기값은 `Vector3.zero`로 두면 된다.
- float 값에는 `Mathf.Lerp` / `Mathf.SmoothDamp`가 동일한 개념으로 존재한다.

### 4.2 Cinemachine으로 대체하기

이전에 시네머신이라는 패키지로 장면을 전환하거나 카메라 움직임을 구현을 한다고 들은 적이 있어 설치해보았다.

**핵심 구조**
- `CinemachineBrain` — 메인 카메라(Main Camera)에 붙는 컴포넌트. 여러 `CinemachineCamera` 중 어떤 걸 실제로 화면에 보여줄지 결정하는 역할만 한다.
- `CinemachineCamera` — 실제로 "어떻게 따라다니고 어디를 바라볼지"를 정의하는 별도 GameObject. 여러 개를 만들어 우선순위(Priority)로 전환 가능하다.

**설정 절차**
1. 플레이어 오브젝트를 먼저 선택
2. `GameObject → Cinemachine → Targeted Cameras → Follow Camera` 선택 → `CinemachineCamera` + Follow(Position Control) + Rotation Composer(Rotation Control) 컴포넌트가 자동 생성됨
3. Main Camera에 `CinemachineBrain`이 붙어있는지 확인
4. `Tracking Target`에 플레이어 지정 (1번을 먼저 했다면 자동 채워짐)

**코드와 대응되는 설정값**
| 코드 구현 | Cinemachine 설정 |
|---|---|
| `distance_y`, `distance_z` (오프셋) | Follow Offset |
| `Vector3.SmoothDamp`, `smoothTime` | Follow Damping |
| — | Rotation Composer의 Screen Composition(화면 구도) |

개념적으로 "Position Control(예전 이름 Body)"은 카메라를 어디에 둘지, "Rotation Control(예전 이름 Aim)"은 어디를 바라보게 할지를 각각 독립적인 알고리즘으로 조합하는 구조다. 직접 짠 스크립트는 이 둘을 한 함수에 합쳐놓은 것과 같다.

## 5. 

1. **velocity(비율) vs 위치/거리(절대값)** — 어떤 API가 "초당 속도"를 받는지 "이번 프레임 이동량"을 받는지 구분해야 `Time.deltaTime`을 곱할지 말지가 정해진다.
2. `verticalVelocity`라는 변수 하나가 양수에서 시작해 중력에 의해 자연스럽게 음수로 넘어가는 것뿐, "점프 중/아닌 중"을 따로 분기해서 특수 처리할 필요가 없다.
3. **CharacterController는 물리를 스스로 구현해야 한다** — 중력, 점프 모두 직접 계산. 대신 `isGrounded`, 경사/계단 처리는 자동으로 해준다.
4. **어트리뷰트 인자는 타입 정보(`typeof`)만 가능** — 인스턴스를 넘길 수 없는 것도, `RequireComponent`가 애초에 "타입 존재 여부"만 검사하기 때문이었다.
