## 1. Gameplay Framework: 프로젝트 → 레벨 → 게임 모드 → 폰

### 구조

```
프로젝트
 ├─ 레벨 A ──▶ 게임 모드 X
 ├─ 레벨 B ──▶ 게임 모드 X   (여러 레벨이 공유 가능)
 └─ 레벨 C ──▶ 게임 모드 Y

게임 모드
 ├─ 디폴트 폰 클래스          ← 플레이어가 조종할 대상
 ├─ 플레이어 컨트롤러 클래스   ← 입력을 받아 폰을 조종
 ├─ HUD 클래스                ← 화면 UI
 ├─ 게임 스테이트 클래스       ← 게임 전체 상태 (남은 시간, 팀 점수)
 └─ 플레이어 스테이트 클래스   ← 플레이어별 상태 (개인 점수, 이름)
```

### 용어

| 용어 | 정의 |
|---|---|
| **프로젝트** | 게임 전체. 여러 레벨과 에셋을 가짐 |
| **레벨 (Level)** | 오브젝트가 배치된 공간(맵). 사용할 게임 모드를 하나 지정 |
| **게임 모드 (GameMode)** | 레벨에서 사용할 클래스들을 **변수로 지정**하고 게임 규칙을 관리하는 클래스 |
| **액터 (Actor)** | 레벨에 배치되는 모든 것 |
| **폰 (Pawn)** | 조종될 수 있는 액터 |
| **캐릭터 (Character)** | 걷기·점프 기능이 들어간 폰 |
| **플레이어 컨트롤러** | 플레이어의 입력을 받아 폰을 조종하는 주체 |
| **PlayerStart** | 폰이 생성되는 위치 표시 |
| **GameInstance** | 레벨이 바뀌어도 유지되는 데이터 보관소 |

### 플레이 시작 시 흐름

1. 레벨이 열림
2. 레벨이 지정한 게임 모드 확인 (없으면 프로젝트 기본값)
3. 게임 모드의 **디폴트 폰 클래스** 확인
4. **PlayerStart** 위치에 그 폰을 생성(Spawn)
5. **플레이어 컨트롤러**가 폰에 빙의(Possess) → 조종 가능

### 설정 위치

| 설정 | 메뉴 위치 | 적용 범위 |
|---|---|---|
| 기본 게임 모드 | 편집 → 프로젝트 세팅 → 맵 & 모드 | 프로젝트 전체 |
| 게임 모드 오버라이드 | 창 → 월드 세팅 → 게임 모드 | 해당 레벨만 |
| 디폴트 폰 클래스 등 | 게임 모드 블루프린트 → 클래스 디폴트 | 그 게임 모드를 쓰는 모든 레벨 |

### 주의 사항 (AI가 말한는)

- 레벨은 게임 모드를 **소유하지 않고 지정(참조)** 합니다. 게임 모드는 별개의 파일입니다.
- 게임 모드는 캐릭터를 담고 있지 않고, **"이 클래스로 만들어라"라는 지정만** 가집니다.
- 월드 세팅에서 디폴트 폰을 바꾸면 **게임 모드 파일 자체가 수정**되어, 같은 게임 모드를 쓰는 모든 레벨에 적용됩니다. 한 레벨만 바꾸려면 게임 모드를 복제해서 지정합니다.
- 데이터 위치: 캐릭터 정보(속도, 체력) → Character / 입력 처리 → PlayerController / 규칙 → GameMode
- 멀티플레이에서 게임 모드는 **서버에만** 존재합니다.

## 2. 블루프린트 클래스와 컴포넌트

### 블루프린트 클래스

- **액터의 설계도**입니다. 하나 만들어 두면 레벨에 여러 개를 배치(인스턴스)할 수 있습니다.
- 변경 후 **컴파일**해야 반영됩니다.

### 컴포넌트의 종류

```
씬 컴포넌트 (Scene Component)
 │  가진 것: 위치, 회전, 스케일
 │  보이지 않고 충돌 없음 → 기준점, 묶음용
 │  예: DefaultSceneRoot, 경첩(Hinge)
 │
 └─ 프리미티브 컴포넌트 (Primitive Component)
       추가로 가진 것: 모양 → 렌더링, 충돌 가능
       예: Static Mesh, Box Collision, Capsule
```

- 디테일 패널에 **콜리전 항목이 없으면** 씬 컴포넌트입니다. (유니티의 빈 오브젝트와 비슷한 개념)
- `DefaultSceneRoot`의 회색 공 아이콘은 에디터 전용 표시이며 게임에서는 보이지 않습니다.

### 부모-자식 관계

| 부모를 바꾸면 | 자식은 |
|---|---|
| 이동 | 함께 이동 |
| 회전 | **부모 위치를 축으로** 함께 회전 |
| 스케일 | 함께 커지거나 작아짐 |

- 새 컴포넌트는 **현재 선택된 컴포넌트의 자식**으로 붙습니다.
- 컴포넌트를 끌어서 다른 컴포넌트 위에 놓으면 부모가 바뀝니다.

### 피벗과 회전축

- 컴포넌트는 **자기 위치(피벗)를 중심으로** 회전합니다.
- 피벗이 원하는 회전축에 없으면, **보이지 않는 씬 컴포넌트를 축 위치에 두고 그 자식으로 메시를 붙인 뒤 씬 컴포넌트를 회전**시킵니다.

```
[피벗이 가운데]          [씬 컴포넌트를 축으로]
   ───●───                ●───────
   팽이처럼 돎             ●
                           ╲  문처럼 열림
```

**예시 구조 (문):**
```
DefaultSceneRoot
 ├ Hinge (Scene)          ← 회전시키는 대상
 │  └ Door (Static Mesh)  ← 한쪽 끝이 Hinge에 오도록 옆으로 밀어 배치
 └ Trigger (Box Collision) ← Hinge와 같은 단계 → 함께 돌지 않음
```

## 3. 좌표계와 트랜스폼

| 축 | 색 | 방향 | 회전 이름 |
|---|---|---|---|
| X | 빨강 | 앞 | Roll |
| Y | 초록 | 오른쪽 | Pitch |
| Z | 파랑 | **위** | **Yaw** (수평 회전) |

- 언리얼은 **Z축이 위쪽**입니다.
- 단위: **1 = 1cm**
- **Pitch(Y)는 −90 ~ 90도로 표시가 제한**됩니다. Yaw(Z)는 제한이 없습니다.

### 월드 기준과 로컬 기준

| 기준 | 의미 |
|---|---|
| 월드 기준 | 레벨 전체의 고정된 방향 |
| 로컬(액터) 기준 | 액터가 **바라보는 방향이 X**. 액터가 돌면 X도 함께 돎 |

| 방향 | 얻는 노드 |
|---|---|
| 앞 (X) | `Get Actor Forward Vector` |
| 오른쪽 (Y) | `Get Actor Right Vector` |
| 위 (Z) | `Get Actor Up Vector` |

- 외부에서 가져온 모델은 앞 방향이 X가 아닐 수 있습니다. 3인칭 템플릿 캐릭터의 Mesh가 **Yaw −90도**로 회전되어 있는 것도 모델의 앞을 X에 맞추기 위해서입니다.
- Arrow 컴포넌트는 액터의 앞(X) 방향을 표시합니다.

### 유니티와 비교

```
        [언리얼]                         [유니티]

          Z (위)                           Y (위)
          │                                │    Z (앞)
          │                                │   ╱
          │                                │  ╱
          │                                │ ╱
          └────────── Y (오른쪽)           └────────── X (오른쪽)
         ╱
        ╱
       X (앞)
```

| 항목 | 언리얼 | 유니티 |
|---|---|---|
| 앞 | **X** | **Z** |
| 오른쪽 | **Y** | **X** |
| 위 | **Z** | **Y** |
| 좌표계 | 왼손 좌표계 | 왼손 좌표계 |
| 기본 단위 | 1 = **1cm** | 1 = **1m** |
| 수평 회전(Yaw) 축 | Z | Y |
| 앞 방향 얻기 | `Get Actor Forward Vector` | `transform.forward` |
| 오른쪽 방향 얻기 | `Get Actor Right Vector` | `transform.right` |
| 위 방향 얻기 | `Get Actor Up Vector` | `transform.up` |

**같은 위치를 표현할 때:**

| 의미 | 언리얼 (X, Y, Z) | 유니티 (X, Y, Z) |
|---|---|---|
| 앞으로 1m | (100, 0, 0) | (0, 0, 1) |
| 오른쪽으로 1m | (0, 100, 0) | (1, 0, 0) |
| 위로 1m | (0, 0, 100) | (0, 1, 0) |

```
변환 공식: 유니티 (x, y, z)  →  언리얼 (z × 100, x × 100, y × 100)
```

- 두 엔진 모두 왼손 좌표계라서, **축 이름만 바꾸면** 방향 관계는 같습니다.
- 유니티에서 가져온 모델이나 수치를 쓸 때는 **축 순서와 100배 단위 차이**를 함께 확인해야 합니다.

### 트랜스폼

| 항목 | 의미 |
|---|---|
| 위치 (Location) | 어디에 있는가 |
| 회전 (Rotation) | 어느 방향을 보는가 |
| 스케일 (Scale) | 원래 크기의 몇 배인가 |

### Relative vs World

| 종류 | 기준 | 사용 |
|---|---|---|
| **Relative** | 부모 기준 | 액터 안의 부품을 움직일 때 (문짝, 팔) |
| World | 월드 원점 기준 | 절대 위치가 필요할 때 |

- Relative를 쓰면 액터를 레벨에 비스듬히 배치해도 부품이 올바르게 움직입니다.

## 4. 변수

### 용도

블루프린트가 기억하는 값입니다. **인스턴스 편집 가능**으로 설정하면 레벨에 배치한 개체마다 값을 다르게 줄 수 있습니다.

### 사용법

| 항목 | 방법 |
|---|---|
| 만들기 | 내 블루프린트 → 변수 줄의 `⊕` |
| 타입 지정 | 디테일 패널 → 변수 타입 |
| 인스턴스 편집 가능 | 디테일 패널 체크박스 (눈 아이콘) |
| 기본값 | **컴파일 후** 디테일 패널 하단 |
| 그래프에서 사용 | 그래프로 끌어다 놓기 → Get(읽기) / Set(쓰기) |

### 주요 타입과 색

| 타입 | 색 | 값 |
|---|---|---|
| Boolean | 빨강 | 참/거짓 |
| Integer | 청록 | 정수 |
| Float | 초록 | 실수 |
| Vector | 노랑 | X, Y, Z (위치·방향) |
| Rotator | 보라 | Roll, Pitch, Yaw (회전) |
| Transform | 주황 | 위치 + 회전 + 스케일 |
| 오브젝트 참조 | 파랑 | 액터·컴포넌트 |

### 구조체 (Struct)

- **여러 값을 하나로 묶은 타입**입니다. (Vector, Rotator, Transform)
- 구조체 핀에 값 하나만 넣으려면: 핀 우클릭 → **구조체 핀 분할**, 또는 `Make Rotator` 같은 Make 노드 사용

### 주의 사항

- 이름은 영어로, 띄어쓰기 없이, 단어 첫 글자를 대문자로 씁니다. Boolean은 앞에 `b`를 붙이는 것이 관례입니다. (`OpenAngle`, `bIsOpen`)
- 타입이 다른 핀끼리는 바로 연결되지 않습니다.

## 5. 충돌 (Collision)

### 반응 세 가지

| 반응 | 통과 | 발생 이벤트 | 예시 |
|---|---|---|---|
| **Block** | 불가 | Hit | 벽, 닫힌 문 |
| **Overlap** | 가능 | Begin / End Overlap | 감지 영역, 아이템 |
| **Ignore** | 가능 | 없음 | 장식 |

### 충돌 설정의 구성

프리미티브 컴포넌트마다 두 가지를 가집니다.

1. **오브젝트 타입:** "나는 무엇인가?"
2. **반응 목록:** "각 타입을 만나면 나는 어떻게 할까?"

### 결과 결정 규칙

```
Ignore  <  Overlap  <  Block      → 두 반응 중 더 약한 쪽을 따름
```

| 내 반응 | 상대 반응 | 결과 |
|---|---|---|
| Block | Block | Block |
| Block | Overlap | Overlap |
| Overlap | Overlap | Overlap |
| 무엇이든 | Ignore | Ignore |

**예시:**

| 조합 | 결과 |
|---|---|
| 캐릭터 캡슐(Pawn, Block) ↔ 문(WorldStatic, Block) | Block → 못 지나감 |
| 캐릭터 캡슐(Pawn, Block) ↔ 감지 영역(WorldDynamic, Overlap) | Overlap → 통과 + 이벤트 |

### 기본 오브젝트 타입

| 타입 | 의미 |
|---|---|
| WorldStatic | 움직이지 않는 물체 (벽, 바닥) |
| WorldDynamic | 움직이는 물체 (트리거, 움직이는 발판) |
| Pawn | 조종되는 대상 (캐릭터 캡슐) |
| PhysicsBody | 물리 시뮬레이션 대상 |
| Vehicle | 차량 |
| Destructible | 파괴 가능한 물체 |

### 자주 쓰는 콜리전 프리셋

| 프리셋 | 동작 | 용도 |
|---|---|---|
| BlockAll | 모두 막음 | 벽, 문 |
| OverlapAllDynamic | 겹침 감지 | 트리거, 아이템 |
| NoCollision | 충돌 없음 | 장식 |
| Pawn | 캐릭터용 | 캐릭터 캡슐 |

### 주의 사항

- 충돌은 **액터가 아니라 컴포넌트 단위**입니다. 한 액터 안에서도 컴포넌트마다 다르게 설정할 수 있습니다.
- Overlap 이벤트는 **양쪽 모두 `오버랩 이벤트 생성`이 켜져 있어야** 발생합니다.
- 메시 모양과 충돌 모양은 다를 수 있습니다. 캐릭터는 사람 모양이지만 충돌은 단순한 캡슐로 계산합니다.

## 6. "막는 충돌"과 "감지하는 충돌"의 분리

### 개념

| 역할 | 컴포넌트 예 | 모양 | 움직임 |
|---|---|---|---|
| **막기** (Block) | 문 메시 | 물체 모양 그대로 | 물체와 함께 움직임 |
| **감지** (Overlap) | 박스 콜리전 | 감지하고 싶은 범위 | 고정 |

감지 영역은 물체 크기가 아니라 **"사람이 다가오는 범위"** 입니다. 자동문 위 센서가 문짝이 아니라 문 앞 바닥을 감지하는 것과 같습니다.

### 감지 영역을 물체보다 크게 잡는 이유

1. **반응에 시간이 걸리기 때문:** 문이 열리는 동안 플레이어가 도착하면 부딪힙니다.
   `감지 거리 ÷ 이동 속도 ≥ 반응 시간` 이 되어야 합니다.
   예) 걷기 속도 약 500cm/s, 감지 거리 150cm → 0.3초 만에 도착
2. **Block에 먼저 막히기 때문:** 감지 영역이 문 크기와 같으면 플레이어가 닫힌 문에 막혀 영역 안으로 들어가지 못합니다.
3. **자연스러운 플레이 감각:** 멈추지 않고 지나갈 수 있어야 매끄럽게 느껴집니다.

### 주의 사항

- 감지 영역을 움직이는 부품의 자식으로 두면 함께 돌아가서, 영역을 벗어나는 순간 End Overlap이 발생해 **열림과 닫힘이 반복**됩니다.
- 너무 크면 근처를 지나가기만 해도 반응합니다. **다가오는 방향만 길게, 옆은 좁게** 잡습니다.
- 같은 패턴: 적 AI 시야 범위, 자동 발판, 컷신 시작 지점

## 7. 이벤트 그래프와 노드

### 노드와 핀

| 요소 | 의미 |
|---|---|
| **이벤트 노드** (빨간 머리) | 특정 상황에서 자동으로 실행되는 시작점 |
| **함수 노드** (`f` 아이콘) | 동작을 수행 |
| **실행 핀** (흰 삼각형) | 실행 순서. 흰 선이 끊기면 노드가 실행되지 않음 |
| **데이터 핀** (색 동그라미) | 값을 주고받음 |
| **Target 핀** | 동작을 **누구에게** 할지 지정 |

### 자주 쓰는 이벤트

| 이벤트 | 실행 시점 |
|---|---|
| Event BeginPlay | 게임 시작 시 한 번 |
| Event Tick | 매 프레임 |
| On Component Begin Overlap | 영역에 들어왔을 때 |
| On Component End Overlap | 영역에서 나갔을 때 |

- 컴포넌트 이벤트 추가: 컴포넌트 선택 → 디테일 패널 맨 아래 **이벤트** → 초록 `+`

### 노드를 만드는 세 가지 방법

| 방법 | 특징 |
|---|---|
| 빈 곳 우클릭 | 전체 노드 검색 |
| 핀을 끌어서 빈 곳에 놓기 | 그 핀에 연결 가능한 노드만 검색 + **자동 연결** |
| 컴포넌트·변수를 그래프로 끌기 | 참조 / Get / Set 노드 생성 |

### 주의 사항

- 연결할 때 **초록 체크가 뜨는지** 확인합니다. 다른 표시면 타입이 맞지 않습니다.
- 검색 결과에는 이름이 비슷한 노드가 많습니다. **아이콘**(시계 = 타임라인, `f` = 함수, 다이아몬드 = 이벤트)까지 확인합니다.
- **Tick에 무거운 로직을 넣지 않습니다.** 매 프레임 실행되기 때문입니다.
- 시간에 따라 변하는 값에는 **Delta Seconds를 곱해야** 프레임레이트와 무관하게 일정한 속도가 됩니다.

## 8. 타임라인과 Lerp

### 역할 분담

```
[타임라인]  시간 → Alpha(진행률)     "지금 몇 % 진행됐어?"
[Lerp]     Alpha → 실제 값          "그럼 값은 얼마야?"
```

### 타임라인

정해진 시간 동안 **0 → 1로 변하는 값(Alpha)** 을 만들어 주는 노드입니다.

| 핀 | 위치 | 의미 |
|---|---|---|
| Play | 입력 | 현재 위치에서 정방향 재생 |
| Play from Start | 입력 | 처음부터 정방향 재생 |
| Stop | 입력 | 멈춤 |
| Reverse | 입력 | 현재 위치에서 역방향 재생 |
| Reverse from End | 입력 | 끝에서부터 역방향 재생 |
| **Update** | 출력 | 재생 중 **매 프레임** 실행 |
| Finished | 출력 | 재생이 끝났을 때 **한 번** 실행 |
| Direction | 출력 | 현재 재생 방향 |
| (트랙 이름) | 출력 | 트랙의 현재 값 |

- 그래프 **가로축 = 시간(초)**, **세로축 = 값**
- **기울기 = 속도.** 키 시간을 줄이면 빨라지고 늘리면 느려집니다.
- 키 우클릭 → `자동`: S자 곡선이 되어 가속·감속이 자연스러워집니다.

### Lerp (선형 보간)

```latex
결과 = A + (B - A) × Alpha
```

| Alpha | 결과 (A = 0, B = 90) |
|---|---|
| 0 | 0 |
| 0.25 | 22.5 |
| 0.5 | 45 |
| 1 | 90 |

### 예시 (문 여닫기)

```
[Begin Overlap] ──▶ Play    ┐
                            ├─[타임라인]── Update ──▶ [Set Relative Rotation]
[End Overlap]   ──▶ Reverse ┘      │ Alpha             Target ◀── Hinge
                                   ▼                    Z (Yaw) ◀── Lerp 결과
                               [Lerp]  A = 0
                                       B ◀── OpenAngle
```

### 주의 사항

- **Alpha는 시간이 아니라 진행률(0 ~ 1)** 입니다. 시간은 타임라인 가로축이 담당합니다.
- **`Play`를 씁니다.** `Play from Start`는 도중에 다시 시작하면 값이 0으로 튑니다.
- **`Update`에 연결합니다.** `Finished`에 연결하면 끝났을 때 한 번만 실행되어 순간 이동처럼 보입니다.
- 키의 시간이 타임라인 **길이**보다 크면 그 키에 도달하지 않습니다.
- 시간(타임라인)과 값 범위(Lerp)를 나누면, 값만 바꿔도 속도·느낌이 유지되고 **Alpha 하나로 여러 값을 동시에** 움직일 수 있습니다.

## 9. 자주 하는 실수

| 증상 | 원인 | 해결 |
|---|---|---|
| 플레이 중 캐릭터가 안 움직임 | 뷰포트 포커스 없음 / 한글 입력 상태 | 뷰포트 클릭, 영문 입력으로 전환 |
| 변경이 반영되지 않음 | 컴파일 안 함 | 컴파일 → 저장 |
| 기본값 칸이 없음 | 컴파일 안 함 | 컴파일 후 확인 |
| 물체가 제자리에서 팽이처럼 돎 | 피벗 위치 | 씬 컴포넌트를 회전축으로 사용 |
| 핀을 놓았더니 검색 메뉴가 뜸 | 핀이 아닌 빈 곳에 놓음 | 그 메뉴로 노드를 만들거나, 초록 체크일 때 놓기 |
| Float가 Rotator에 안 꽂힘 | 타입 불일치 | 구조체 핀 분할 |
| 원하는 노드 대신 다른 노드가 생김 | 비슷한 이름 선택 | 아이콘과 이름 끝까지 확인 |
| 타임라인 편집기가 안 보임 | 새 창이 아니라 탭으로 열림 | 가운데 탭 줄 확인 |
| Overlap 이벤트가 안 생김 | 오버랩 이벤트 생성 꺼짐 / 감지 영역이 Block에 가려짐 | 설정 확인, 감지 영역 확장 |
| 경로·이름 관련 빌드 오류 | 한글·공백 포함 | 영문, 공백 없는 경로와 이름 사용 |
