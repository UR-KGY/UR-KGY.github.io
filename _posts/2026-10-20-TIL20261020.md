## 2. 서버 코드 변경

### 2-1. 상점 결제 방식

- `PriceType`(GOLD, DIAMOND, FREE, CASH) 도입 — PR #19
- 마이그레이션 `V20261020_1030__change_shop_price_type_to_varchar.sql`
- FREE는 차감 없이 지급, CASH는 시트 검증에서 차단

### 2-2. 가챠 등급 랜덤 — PR #20 + 후속 수정

| 파일 | 변경 내용 |
| --- | --- |
| `GachaGrade` (신규) | 시트 grade 전용 enum, `NONE` → null 변환 |
| `GachaEntry` | `grade` 필드, `equipmentGrade()`, `isRandomArtifact()` |
| `GachaEntryTable` | grade·rewardCode 조합 검증, 등급 랜덤 행 amount = 1 강제 |
| `GachaCatalog` | artifact 시트를 등급별로 묶어 `Candidate`/`Pool` 생성, 지정 행은 코드 존재만 검사 |
| `GachaPicker` | 2단계 추첨 (행 weight → 같은 등급 내 균등) |
| 테스트 | `GachaEntry` 생성자에 `GachaGrade.NONE` 반영 |

**추첨 확률**

```
아티팩트 1종 확률 = (행 weight ÷ 같은 gachaCode weight 합) × (1 ÷ 해당 등급 아티팩트 수)
```

**결정 사항**

- rewardCode가 있는 지정 행의 grade는 **무시** (시트 표기 불일치로 인한 부팅 실패 해소)
- 상자 횟수는 `shopProductRewards`의 GACHA_BOX amount, 등급 랜덤 행 amount는 1 고정
  - 원인: 행 amount 10 × 상자 10회 = 결과 100건 지급 버그
  - `GachaService`의 `MAX_OPEN`(10)은 상자 횟수만 검사하므로 행 amount는 걸러지지 않았음

### 2-3. 기타

- `Enemy`의 `appearanceCode` 제거 (테스트 2곳은 담당자 수정 예정)
- workflow에 `main` push 트리거 추가 (deploy-test는 추후 제외 예정)

## 3. AWS 변경

| 대상 | 변경 |
| --- | --- |
| Parameter Store | `/swordmaster/prod/GOOGLE_WEB_CLIENT_ID` 추가 |
| 시작 템플릿 | v5 생성 — user-data에 `getp GOOGLE_WEB_CLIENT_ID` + `-e GOOGLE_WEB_CLIENT_ID` 추가, 기본 버전 5 |
| ASG | 시작 템플릿 버전 `Default` 사용 확인 |
| IAM `sword-master-ec2-role` | `/swordmaster/prod/*` 읽기 권한 확인 (수정 없음) |
| IAM `github-actions-swordmaster-deploy` | 배포용 역할 확인 (수정 없음) |

**환경변수 추가 절차 (하나라도 빠지면 부팅 실패)**

1. Parameter Store에 `/swordmaster/prod/KEY` 생성 — 값은 실제 값
2. 시작 템플릿 새 버전: user-data에 `KEY=$(retry getp KEY)` + `-e KEY="$KEY" \` 추가 → 기본 버전 지정
3. `application-prod.properties`에 `KEY=${KEY}` 추가
4. 배포 후 새 인스턴스의 템플릿 버전 태그 확인
