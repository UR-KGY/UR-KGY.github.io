# Swordmaster 서버 AWS 배포 기록 (2026-10-08 기준)

> 리전: **ap-northeast-2 (서울)**
> 계정 ID, RDS 엔드포인트, 비밀번호, JWT 키 같은 값은 이 문서에 적지 않는다. 필요한 곳은 `<ACCOUNT_ID>`처럼 자리 표시로 남긴다.

---

## 0. 전체 그림

```
[내 PC]                                      [AWS - VPC]
 jar 빌드 → Docker 이미지 빌드 ── push ──▶  ECR (이미지 창고)
                                               │ pull (NAT 경유)
                                               ▼
 Session Manager ── 명령 입력 ──▶   EC2 (private 서브넷, Docker)
                                               │  환경변수 ◀── Parameter Store (비밀값)
                                               ▼
                                             RDS MySQL (private 서브넷)
```

| 구성 요소 | 한 줄 역할 |
|---|---|
| VPC / 서브넷 | 우리 서버들만 쓰는 사설 네트워크 |
| IGW | VPC와 인터넷을 잇는 대문 |
| NAT 게이트웨이 | private 서브넷의 서버가 **밖으로만** 나갈 수 있게 해 주는 출구 |
| EC2 | 실제로 Spring 서버(Docker 컨테이너)가 돌아가는 컴퓨터 |
| RDS | AWS가 관리해 주는 MySQL |
| Parameter Store | DB 비밀번호, JWT 키 같은 비밀값 보관함 |
| ECR | Docker 이미지 보관 창고 |
| IAM 역할 | EC2에 붙이는 신분증 (액세스 키 없이 AWS 서비스 사용) |
| Session Manager | SSH 키 없이 브라우저로 EC2에 접속하는 원격 터미널 |

진행 상태: **VPC ✅ → EC2 ✅ → RDS ✅ → Parameter Store ✅ → ECR ✅ → 컨테이너 실행 ✅ (validate 전환 대기) → 시작 템플릿 v2 ⏳**

## 1. VPC / 네트워크

### 한 일
- VPC 마법사로 VPC, public/private 서브넷, IGW, NAT 게이트웨이(영역별 NAT)를 함께 생성
- private 서브넷 라우팅 테이블: `0.0.0.0/0 → NAT`
- public 서브넷 라우팅 테이블: `0.0.0.0/0 → IGW`
- NACL은 기본값 유지 (보안은 보안그룹으로 관리)

### 의미
- **public 서브넷**: 인터넷에서 직접 들어올 수 있는 구역. NAT와 (나중에) ALB가 위치
- **private 서브넷**: 밖에서 들어올 수 없는 구역. EC2와 RDS를 여기에 두어 외부 공격 경로를 없앰
- **NAT**: private의 EC2가 Google Sheet 다운로드, ECR pull, 패키지 설치처럼 **밖으로 나가는 요청**만 할 수 있게 해 줌
- **Regional NAT**: 여러 AZ를 하나로 처리하는 신규 방식. 지금은 마법사가 만든 영역별 NAT 사용

### 확인 결과
- EC2에서 `curl docs.google.com` → **302** (NAT 통한 외부 통신 정상)

### 비용 주의
- NAT 게이트웨이는 켜져 있는 동안 **시간당 요금 + 데이터 처리 요금**이 붙음 (월 약 $45~50)
- 프리 플랜 크레딧에서 차감됨. 장기간 안 쓸 때는 NAT 삭제를 고려

## 2. 보안그룹

| 보안그룹 | 붙는 곳 | 인바운드 | 아웃바운드 |
|---|---|---|---|
| `app-sg` | EC2 | 없음 (Session Manager는 인바운드 불필요). 나중에 ALB 붙이면 `8080 ← alb-sg` | 전체 허용 (NAT 통해 ECR, SSM, Google 접근) |
| `rds-sg` | RDS | `3306 ← app-sg` | 기본값 |
| `alb-sg` (예정) | ALB | `80/443 ← 0.0.0.0/0` | `8080 → app-sg` |

### 의미
- 보안그룹은 **리소스마다 붙는 방화벽**이다
- 출처를 IP가 아니라 **다른 보안그룹(app-sg)**으로 지정하면, app-sg가 붙은 서버만 DB에 접근할 수 있다. EC2가 바뀌어 IP가 달라져도 규칙을 고칠 필요가 없다
- Session Manager는 EC2가 **바깥(SSM 서비스)으로 연결을 거는** 방식이라 인바운드 포트(22)를 열 필요가 없다

## 3. IAM 역할 (`sword-master-ec2-role`)

| 정책 | 종류 | 용도 |
|---|---|---|
| `AmazonSSMManagedInstanceCore` | AWS 관리형 | Session Manager 접속 |
| `AmazonEC2ContainerRegistryReadOnly` | AWS 관리형 | ECR 로그인 + 이미지 pull (push 불가) |
| Parameter Store 읽기 (인라인) | 직접 작성 | `/swordmaster/prod/*` 값 읽기만 허용 |

인라인 정책:
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["ssm:GetParameter", "ssm:GetParameters"],
      "Resource": "arn:aws:ssm:ap-northeast-2:<ACCOUNT_ID>:parameter/swordmaster/prod/*"
    }
  ]
}
```

### 의미
- EC2에 **액세스 키를 넣지 않고**, 역할(신분증)로 권한을 받는다. 키가 유출될 걱정이 없다
- **최소 권한 원칙**: EC2는 이미지를 받기만 하고(ReadOnly), 파라미터도 이 경로만 읽는다
- 역할 이름은 `sword-master-ec2-role`(하이픈 있음), 파라미터 경로는 `/swordmaster/`(하이픈 없음). 헷갈리지 말 것

### 확인 결과
- `aws sts get-caller-identity` → `assumed-role/sword-master-ec2-role/i-...`

## 4. EC2 + 시작 템플릿 v1

### 설정
| 항목 | 값 | 이유 |
|---|---|---|
| 인스턴스 유형 | t4g.small (ARM, 2GB) | 프리 플랜 대상. ARM이라 이미지도 arm64로 빌드해야 함 |
| 서브넷 | private 서브넷 1 (ap-northeast-2a) | 외부 직접 접근 차단 |
| 퍼블릭 IP | 없음 | private 서브넷 설정을 따름 |
| 키 페어 | 없음 | Session Manager로 접속 |
| IMDSv2 | 필수, 홉 제한 1 | 메타데이터 탈취 공격 방어. 컨테이너가 EC2 자격증명을 직접 못 읽게 함 |
| 스토리지 | gp3 | GB당 월 약 $0.0912 |

시작 템플릿 **v1 사용자 데이터** (Docker 설치):
```bash
#!/bin/bash
set -euo pipefail
dnf update -y
dnf install -y docker
systemctl enable --now docker
usermod -aG docker ssm-user || true
```

### 의미
- **시작 템플릿**: EC2를 만들 때의 설정을 저장한 "주문서". 버전(v1, v2…)으로 관리하고 Auto Scaling이 이걸 보고 서버를 찍어 낸다
- **사용자 데이터**: EC2가 **처음 부팅할 때 딱 한 번** 실행되는 스크립트 (cloud-init)
- 서버에 데이터를 저장하지 않는 구조(Stateless: 세션 없음, DB는 RDS)라서 서버를 언제든 새로 찍어 내도 된다

### 겪은 문제
| 현상 | 원인 | 결론 |
|---|---|---|
| 템플릿으로 시작 시 키 페어/서브넷 에러 | 템플릿에 비워 둔 항목이고, 기본 VPC가 없어서 직접 선택 필요 | "키 페어 없이 진행", private 서브넷 1 선택 |
| 퍼블릭 IP 옵션이 안 보임 | 서브넷 설정을 따름 | 정상 |
| `usermod: user 'ssm-user' does not exist` | ssm-user는 첫 Session Manager 접속 때 생성됨 | 무해. 대신 docker 명령에 `sudo` 필요 |
| 인스턴스가 aarch64 | t4g는 ARM CPU | 이미지 빌드에 `--platform linux/arm64` 필수 |

### 확인 결과
- Session Manager 접속 정상, Docker 설치 정상, `free -h` 가용 메모리 약 1.3GiB

## 5. RDS (MySQL)

### 설정
- private 서브넷 그룹에 생성, 퍼블릭 액세스 없음
- 보안그룹 `rds-sg` (3306 ← app-sg)
- DB 이름 `swordmaster` 확인 완료 (MySQL 8.4)

### 의미
- RDS는 백업, 패치, 장애 복구를 AWS가 대신 해 주는 DB
- private 서브넷 + 보안그룹으로 **EC2에서만** 접근 가능

### 운영 메모
- **마스터 비밀번호는 다시 볼 수 없다.** 잊으면 RDS → 수정에서 새로 설정
- 비밀번호를 바꾸면 **Parameter Store의 `DB_PASSWORD`도 갱신하고 컨테이너를 재시작**해야 함

## 6. Parameter Store

| 이름 | 타입 | 내용 |
|---|---|---|
| `/swordmaster/prod/JWT_SECRET` | SecureString | Base64 인코딩된 32바이트 이상 키 (44자) |
| `/swordmaster/prod/DB_HOST` | String | RDS 엔드포인트 |
| `/swordmaster/prod/DB_USERNAME` | String | DB 사용자 |
| `/swordmaster/prod/DB_PASSWORD` | SecureString | DB 비밀번호 |

### 의미
- 비밀값을 **코드, jar, 이미지 어디에도 넣지 않고** AWS에 따로 보관한다
- SecureString은 KMS로 암호화 저장. 읽을 때 `--with-decryption` 필요
- 컨테이너 실행 시 꺼내서 환경변수로 넘기면, Spring이 설정 파일의 `${DB_HOST}` 같은 자리에 채워 넣는다

### 확인 방법 (값은 출력하지 않고 길이만)
```bash
for n in JWT_SECRET DB_HOST DB_USERNAME DB_PASSWORD; do
  printf '%s: ' "$n"
  aws ssm get-parameter --name "/swordmaster/prod/$n" --with-decryption \
    --region ap-northeast-2 --query 'length(Parameter.Value)' --output text
done
```
결과: 네 값 모두 정상 조회 (Session Manager 화면에서 글자가 겹쳐 보이는 것은 표시 문제)

## 7. 코드 쪽 준비

### 설정 파일
| 파일 | 내용 |
|---|---|
| `application.properties` | `jwt.secret=${JWT_SECRET}` 로 변경 (키 하드코딩 제거) |
| `application-prod.properties` (gitignore) | DB 접속을 `${DB_HOST}`, `${DB_USERNAME}`, `${DB_PASSWORD}`로, `ddl-auto=validate`, `open-in-view=false`, health 노출 |

- prod 설정 파일은 **빈칸(`${...}`)만** 있으므로 jar/이미지에 들어가도 안전
- 실제 값은 실행할 때 환경변수로 들어간다
- 로컬 실행 시에도 `JWT_SECRET` 환경변수 필요 (IntelliJ Run Configuration에 로컬용 키)

### Dockerfile (프로젝트 루트)
```dockerfile
FROM eclipse-temurin:21-jre
WORKDIR /app
COPY build/libs/swordmaster-0.0.1-SNAPSHOT.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```
- jar 하나를 Java 21 실행 환경 위에 올려 실행하는 "레시피"
- `build.gradle`의 version을 바꾸면 jar 파일명도 바꿔야 함

### .dockerignore (프로젝트 루트)
```
.git
.gradle
.idea
.env
src/main/resources/application-prod.properties
```
- docker build 때 Docker로 넘기지 않을 파일 목록
- `.dockerignore`는 **jar 안의 내용에는 영향이 없다.** prod 설정은 bootJar 때 이미 jar 안에 들어감
- `build`는 넣으면 안 됨 (jar가 `build/libs`에 있음)

## 8. 로컬 빌드 → ECR 업로드

### 로컬 환경 준비 (Git Bash)
| 문제 | 원인 | 해결 |
|---|---|---|
| `JAVA_HOME is not set` | Git Bash는 IntelliJ가 받은 JDK 위치를 모름 | 아래 export (또는 `~/.bashrc`에 추가) |

```bash
export JAVA_HOME="/c/Users/0000k/.jdks/ms-21.0.8"
export PATH="$JAVA_HOME/bin:$PATH"
```

- Git Bash에서 `/swordmaster/...` 같은 인자가 Windows 경로로 바뀌는 문제는 `MSYS_NO_PATHCONV=1`을 앞에 붙여 해결
- AWS CLI v2 설치 (`AWSCLIV2.msi`)
- `aws configure`: **IAM 사용자** 키 사용 (루트 키 금지). 권한 `AmazonEC2ContainerRegistryPowerUser`. 리전 `ap-northeast-2`, 출력 `json`
- `aws sts get-caller-identity`의 Arn이 `:user/...`인지 확인

### 단계별 명령과 의미
```bash
# ① jar 빌드 — 서버 프로그램 만들기
./gradlew bootJar -x test
ls build/libs        # swordmaster-0.0.1-SNAPSHOT.jar

# ② 이미지 빌드 — jar + Java 실행 환경을 하나로 포장 (EC2가 ARM이라 arm64)
docker build --platform linux/arm64 --provenance=false --sbom=false -t swordmaster:latest .

# ③ ECR 로그인 — 12시간짜리 출입증 받기
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
REGISTRY="$ACCOUNT_ID.dkr.ecr.ap-northeast-2.amazonaws.com"
aws ecr get-login-password --region ap-northeast-2 \
  | docker login --username AWS --password-stdin "$REGISTRY"

# ④ 태그 + 업로드 — ECR 주소가 적힌 이름표를 붙여서 창고로 보내기
docker tag swordmaster:latest "$REGISTRY/swordmaster:latest"
docker push "$REGISTRY/swordmaster:latest"

# 확인
aws ecr describe-images --repository-name swordmaster --region ap-northeast-2 \
  --query 'imageDetails[].{tag:imageTags[0],pushed:imagePushedAt,bytes:imageSizeInBytes,type:imageManifestMediaType}' \
  --output table
```

### 겪은 문제
| 현상 | 원인 | 해결 |
|---|---|---|
| push 후 ECR에 3줄 (latest 1 + 태그 없음 2) | buildx가 목차(index) + 본문 + 빌드 증명서로 나눠 올림 | `--provenance=false --sbom=false`로 다시 빌드 → `latest`가 `application/vnd.oci.image.manifest.v1+json` (본문 한 장)으로 확인 |
| 크기가 ECR 165MB / EC2 411MB | ECR은 압축 상태, EC2는 압축 해제 상태 | 정상 |

### ECR 수명 주기 정책
| 우선순위 | 대상 | 조건 | 작업 |
|---|---|---|---|
| 1 | 태그 없음 | 이미지 생성 이후 1일 | 만료 |
| 2 | 모두 | 이미지 개수 10 초과 | 만료 |

- `latest`를 새로 올리면 이전 이미지는 태그를 잃는다 → 규칙 1이 하루 뒤 정리
- 규칙 2는 나중에 커밋 해시 태그를 쓸 때를 위한 상한선
- 삭제는 복구 불가. 규칙 변경 시 "테스트 규칙"으로 `latest`가 대상이 아닌지 확인

## 9. EC2에서 pull → 컨테이너 실행

### 역할 구분
- **로컬**에서 한 일: 이미지를 ECR에 **올리기**
- **Session Manager**에서 한 일: EC2의 Docker가 ECR에서 **내려받아 실행**하도록 명령
- 이미지 데이터는 Session Manager를 거치지 않고 **ECR → NAT → EC2**로 이동

### 명령 (Session Manager)
```bash
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
REGISTRY="$ACCOUNT_ID.dkr.ecr.ap-northeast-2.amazonaws.com"

param() {
  aws ssm get-parameter --name "/swordmaster/prod/$1" --with-decryption \
    --region ap-northeast-2 --query Parameter.Value --output text
}

aws ecr get-login-password --region ap-northeast-2 \
  | sudo docker login --username AWS --password-stdin "$REGISTRY"
sudo docker pull "$REGISTRY/swordmaster:latest"

# 첫 실행: 빈 DB에 테이블 생성을 위해 이번만 update
sudo docker run -d --name swordmaster --restart unless-stopped -p 8080:8080 \
  -e SPRING_PROFILES_ACTIVE=prod \
  -e SPRING_JPA_HIBERNATE_DDL_AUTO=update \
  -e JWT_SECRET="$(param JWT_SECRET)" \
  -e DB_HOST="$(param DB_HOST)" \
  -e DB_USERNAME="$(param DB_USERNAME)" \
  -e DB_PASSWORD="$(param DB_PASSWORD)" \
  "$REGISTRY/swordmaster:latest"

sudo docker logs -f swordmaster    # Ctrl+C로 빠져나와도 서버는 계속 실행
```

| 옵션 | 의미 |
|---|---|
| `-d` | 백그라운드 실행 |
| `--restart unless-stopped` | 앱이 죽거나 EC2가 재부팅돼도 자동 재시작 |
| `-p 8080:8080` | EC2 8080 → 컨테이너 8080 연결 |
| `SPRING_JPA_HIBERNATE_DDL_AUTO=update` | **첫 실행 전용**. prod 기본값(validate)을 덮어써서 테이블 생성 |

### 결과
- prod 프로필 활성, **EC2 → RDS 연결 성공**
- 테이블 6개 생성: `users`, `players`, `player_currencies`, `player_artifacts`, `currency_histories`, `shop_purchase_logs`
- UNIQUE 제약 생성 (`uk_shop_purchase_user_request` 등)
- Google Sheet 로드/검증 통과
- `Started SwordmasterApplication in 14.771 seconds`
- `CurrencyBackfillRunner` 실행 (플레이어 0명이라 삽입 0건)

### 겪은 문제
| 현상 | 원인 | 해결 |
|---|---|---|
| `Conflict. The container name "/swordmaster" is already in use` | 같은 이름의 컨테이너가 이미 실행 중 | `sudo docker rm -f swordmaster` 후 다시 실행 (컨테이너만 삭제, 이미지·DB는 유지) |
| `/actuator/health` → **401** | `FilterConfig`가 회원가입/로그인(POST)만 허용하고 나머지는 전부 인증 필요 | 아래 "남은 작업 1" |
| prod인데 SQL이 로그에 출력 | Hibernate 쪽 `show_sql`, `format_sql`, `use_sql_comments`가 켜져 있는 것으로 추정 | 아래 "남은 작업 2" |
| `Using generated security password` 경고 | `UserDetailsService` 빈이 없어 Spring이 임시 계정 생성 | formLogin/httpBasic이 꺼져 있어 **보안 위험 없음**. 정리는 선택 |
| `jwtFilterRegistration was not registered (disabled)` | JWT 필터를 Security 체인에서만 돌리려고 의도적으로 끔 | 정상 |

## 10. 남은 작업 (간략)

1. **헬스 체크 허용** — `FilterConfig`의 `.anyRequest()` **위에** 추가
   ```java
   .requestMatchers(HttpMethod.GET, "/actuator/health").permitAll()
   ```
2. **prod SQL 로그 끄기** — `application-prod.properties`에 추가
   ```properties
   spring.jpa.properties.hibernate.show_sql=false
   spring.jpa.properties.hibernate.format_sql=false
   spring.jpa.properties.hibernate.use_sql_comments=false
   ```
3. **재배포** — 로컬: bootJar → docker build → push / EC2: pull → `docker rm -f` → run
4. **validate 전환** — run 명령에서 `SPRING_JPA_HIBERNATE_DDL_AUTO=update` 줄 제거. 로그에 `create table` 없이 `Started`만 나오면 정상. `curl localhost:8080/actuator/health` → `{"status":"UP"}`
5. **시작 템플릿 v2** — 9번의 로그인/pull/param/run(validate)을 사용자 데이터에 넣어, 새 EC2가 스스로 서버를 띄우게 함 (`set -x` 금지: 비밀값 로그 노출)
6. **ALB + alb-sg** — public 서브넷에 ALB, 헬스 체크 경로 `/actuator/health`, app-sg 인바운드 `8080 ← alb-sg`
7. **(선택) Auto Scaling** — 시작 템플릿 v2 기반. 여러 대 동시 기동 시 `CurrencyBackfillRunner` 충돌 가능성 검토
8. **(선택) CI/CD** — GitHub Actions로 ①~④ 자동화, 이미지 태그에 커밋 해시 추가
9. **(선택) 정리** — `UserDetailsServiceAutoConfiguration` 제외, 재화 담당자에게 `@EnableScheduling` 누락 공유
10. **비용 관리** — NAT 시간당 요금 주의. 쓰지 않는 기간에는 NAT/EC2/RDS 중지·삭제 고려

## 부록: 보안 원칙

- JWT 키, DB 비밀번호, AWS 액세스 키는 **git, 이미지, 채팅, 문서에 넣지 않는다**
- 루트 계정 액세스 키는 만들지도 쓰지도 않는다
