## 1. Docker

Docker는 자바에서 빌드된 프로그램을 내부에서 실행해 줄 수 있는 프로그램이다. (일단 지금 용도로는)
환경을 미리 맞추고 프로그램을 실행하기 때문에 도커를 사용하면 다른 컴퓨터에서 실행하더라도 같은 환경에서 사용할 수 있다.

### 스프링 프로젝트 내에 Dockerfile 생성 (이미지 만들기)

```dockerfile
FROM eclipse-temurin:21-jdk-alpine   # 해당 자바 환경에서 실행

WORKDIR /app                          # 컨테이너의 작업 폴더 위치

COPY build/libs/*.jar /app/myapp.jar  # 복사할 빌드된 파일의 경로와 복사할 경로

ENTRYPOINT ["java","-jar","/app/myapp.jar"]  # 컨테이너 시작 시 실행할 명령어
```

- **Dockerfile** : 현 프로젝트를 빌드한 내용물을 도커에서 어떻게 실행하고 관리할지 나타내는 레시피로 이미지를 생성한다.
- **Image** : 앱 실행에 필요한 것들을 담은 템플릿 (수정 불가)
- **Container** : Image를 기반으로 실행한 프로그램의 세션. 사용 이후 제거해도 무관

### Docker에서 MySQL 띄우기

기존에 로컬에 MySQL을 설치하여 연결하는 방식 대신, 도커에서 설치해서 이미지로 관리하는 방식을 앞으로는 사용한다.

터미널에 입력할 MySQL 컨테이너 생성 명령어:

```bash
docker run -d --name mysql -e MYSQL_ROOT_PASSWORD=12345678 -p 3306:3306 mysql:8.4
```

- `-d` : 백그라운드(detached) 실행
- `--name mysql` : 컨테이너 이름 지정
- `-e MYSQL_ROOT_PASSWORD=12345678` : root 비밀번호 환경변수 (필수, 없으면 초기화 실패)
- `-p 3306:3306` : 호스트포트:컨테이너포트 매핑

Docker의 container 안에서 MySQL을 실행 및 중지가 가능하고, 설정된 포트 번호를 통해 Java에서 연결한다.

## 2. Database

여러 사람이 공유할 목적으로 한 곳에서 관리되는 데이터의 조직화된 집합. 데이터의 집합 저장소.

### 종류

**1. 관계형 DB**
- 가장 많이 사용
- 데이터를 테이블 형태로 구조화하여 저장, 관리
- 테이블 간의 관계를 이용해 데이터 연결
- 예) Oracle, MySQL 등

**2. 비관계형 DB (NoSQL)**
- 테이블이 아닌 Key-Value, Document, Graph 등 다양한 형태로 데이터를 저장, 관리
- 스키마가 고정되지 않고, 대규모 데이터 처리와 확장성을 제공
- 예) MongoDB, Redis 등

### 트랜잭션 (Transaction)

데이터베이스에서 하나의 논리적인 작업 단위를 뜻한다.
트랜잭션으로 묶여있는 작업들은 **'모두 성공적으로 완료'**되거나 **'하나라도 실패하면 전체가 취소'**되거나이다.

### RDBMS

관계형 데이터베이스(RDB)를 관리할 수 있는 소프트웨어를 지칭 (실무에서는 둘 다 같은 단어로 취급).
소프트웨어로 데이터를 테이블 형식으로 관리하며, 데이터 간의 관계를 정의하고 관계를 바탕으로 복잡한 Query를 실행할 수 있는 기능을 제공한다.

#### 1) 테이블

행(row, 가로)과 열(column, 세로)로 구성된 구조.

**테이블 예시 (`members` 테이블)**

| id (PK) | name | age |
|---|---|---|
| 1 | 홍길동 | 25 |
| 2 | 김철수 | 30 |

- 열은 데이터의 속성을 나타내고 타입(데이터 유형)을 가진다. (예: `id`는 정수, `name`은 문자열)
- 행은 관계된 데이터의 묶음을 의미하고 tuple 또는 record라고 한다.

**행(튜플/레코드) 예시**

```
(1, "홍길동", 25)   ← 이 한 줄 전체가 하나의 tuple/record
```

**데이터 무결성**: 테이블은 규칙과 제약 조건(기본 키, 외래 키, 유니크 등)을 통해 데이터를 저장함으로써 데이터의 무결성(정확성, 일관성, 유효성)을 유지한다.

#### 2) 관계

테이블 간의 관계는 외래 키를 통해 설정된다.

**PK-FK 관계 예시**

```
[members 테이블]                [orders 테이블]
id (PK) | name                  id (PK) | member_id (FK) | product
1       | 홍길동                 101     | 1              | 노트북
2       | 김철수                 102     | 1              | 마우스
                                 103     | 2              | 키보드
```
→ `orders.member_id`가 `members.id`를 참조(FK)함으로써 "홍길동(id=1)이 노트북과 마우스를 주문했다"는 관계가 성립한다.

RDBMS는 다양한 유형의 관계를 지원한다.
- **1:1 관계**: 한 테이블의 한 행이 다른 테이블의 한 행과만 연결된 관계
- **1:다 관계**: 한 테이블의 한 행이 다른 여러 테이블(행)과 연결된 관계
- **다:다 관계**: 두 테이블의 여러 행이 서로 연결된 관계 (아직 사례 못 봄)

#### 3) SQL (Structured Query Language)

RDBMS에서 데이터를 정의하고, 관리하기 위한 표준 언어. 데이터를 생성, 읽기, 갱신, 삭제하는 작업을 수행한다.

#### 4) 키

**키 사용 예시**

```sql
CREATE TABLE members (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,   -- 기본 키
    email VARCHAR(100) UNIQUE,               -- 유일 키
    name VARCHAR(50)
);

CREATE TABLE orders (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    member_id BIGINT,
    FOREIGN KEY (member_id) REFERENCES members(id)  -- 외래 키
);
```

- **기본 키 (Primary Key)**: 테이블 내에서 각 행을 고유하게 식별하는 열. 한 테이블 당 하나만 존재. 값의 중복을 허용하지 않고, Null 값을 가질 수 없다.
- **외래 키 (Foreign Key)**: 다른 테이블의 기본 키를 참조하는 열. 두 테이블 간 관계를 설정하는 데 사용된다. 테이블 간의 데이터 무결성 유지 가능.
- **유일 키 (Unique Key)**: 기본 키와 유사하지만 하나의 테이블에서 여러 개가 존재할 수 있다. 중복된 값을 허용하지 않고, Null 값은 허용한다.

#### 5) 트랜잭션 (Transaction)

RDBMS는 트랜잭션이라는 단위로 데이터베이스 작업을 처리한다. 트랜잭션은 원자성, 일관성, 고립성, 지속성이라는 ACID 속성을 따른다.

- **원자성 (Atomicity)**: 모든 작업이 성공적으로 완료되거나, 하나라도 실패 시 모든 작업이 작업 시작 전으로 돌아간다.
- **일관성 (Consistency)**: 트랜잭션이 데이터베이스를 일관된 상태로 유지한다.
- **고립성 (Isolation)**: 동시에 실행되는 트랜잭션 간의 영향을 최소화한다.
- **지속성 (Durability)**: 트랜잭션이 성공적으로 수행된 후 변경된 사항은 영구적으로 저장된다.

#### 6) 데이터 무결성

- **엔티티 무결성**: 각 테이블의 기본 키가 중복되지 않고 Null 값이 아닌 상태를 유지
- **참조 무결성**: 외래 키를 통해 참조되는 데이터가 유효성을 유지하도록 보장
- **도메인 무결성**: 각 열이 정의된 데이터 타입과 제약 조건에 따라 유효한 값을 유지

## 3. SQL

### 1) DDL (Data Definition Language)

DB의 구조를 정의하는 언어.

**CREATE**: 새로운 DB 및 테이블을 생성

```sql
-- DB 생성
CREATE DATABASE shop;

-- 테이블 생성 (여러 속성 포함)
CREATE TABLE members (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    age INT
);
```

**ALTER**: 기존 DB와 테이블의 구조를 수정

```sql
-- 테이블에 새로운 속성(컬럼) 추가
ALTER TABLE members ADD COLUMN phone VARCHAR(20);
```

**DROP**: DB 및 테이블을 삭제

```sql
-- DB 삭제
DROP DATABASE shop;

-- 테이블 삭제
DROP TABLE members;
```

### 2) DML (Data Manipulation Language)

DDL이 DB나 테이블 자체의 생성, 수정, 삭제를 관리한다면, DML은 테이블 안의 내용물(데이터)을 관리한다.

**INSERT**: 테이블에 새로운 데이터를 삽입

```sql
-- 위에서 CREATE로 만든 테이블에 데이터 삽입
INSERT INTO members (name, email, age) VALUES ('홍길동', 'hong@test.com', 25);
```

**UPDATE**: 테이블의 기존 데이터를 수정

```sql
-- INSERT로 만든 데이터의 특정 한 값을 수정
UPDATE members SET age = 26 WHERE id = 1;
```

**DELETE**: 테이블의 특정 데이터를 삭제

```sql
-- 만들었던 데이터를 삭제
DELETE FROM members WHERE id = 1;
```

### 3) DQL (Data Query Language)

테이블 내에서 원하는 데이터를 조회하는 언어.

**SELECT**: 데이터 조회

```sql
-- 조건을 붙이는 예시 (WHERE)
SELECT * FROM members WHERE age >= 20;

-- 특정 컬럼(데이터)만 가져오는 예시
SELECT name, email FROM members;
```

## 4. ERD (Entity Relationship Diagram)

데이터베이스의 구조를 시각적으로 표현하는 도구.

- 데이터베이스 구조를 한눈에 파악할 수 있다.
- 설계를 진행하며 논리적인 오류를 파악하고 수정할 수 있다.
- 데이터 구조를 문서화하여 다른 사람과의 소통을 원활하게 한다. (협업 관점)
- 데이터 구조의 근본적인 결함을 제거하여 기술적 부채를 사전에 방지한다.

**자바 클래스와 ERD의 같은 이름의 Entity가 대응하는 예시**

```
[ERD - members 테이블]              [Java - Member 클래스]
members                              @Entity
├─ id (PK, BIGINT)                   public class Member {
├─ name (VARCHAR)                        @Id
└─ email (VARCHAR)                       private Long id;
                                          private String name;
                                          private String email;
                                      }
```
→ ERD 상의 `members` 테이블 구조가 Java의 `Member` 엔티티 클래스 필드와 1:1로 대응된다.

사실 자바에서 데이터베이스를 사용할 때 다이어그램 표시라는 기능으로 각 테이블 간의 ERD를 확인할 수 있다.

## 5. ORM

관계형 데이터베이스와 객체지향 프로그래밍 언어 간에 데이터 변환 기법.

ORM은 인터페이스.

**ORM이 필요한 이유**

- 데이터베이스의 데이터 칸에는 객체 형식이나 리스트 형식의 데이터가 들어가는 것이 불가능하다.
- 자바의 클래스는 객체 형식이나 리스트 형식의 데이터를 필드로 선언 가능하다.
- 이 둘 사이의 형식 차이를 자동으로 변환해주는 것이 ORM.

## 6. JPA

이전에 자바에서 DB의 데이터를 가져오기 위해선 JDBC라는 것을 사용하며 SQL문을 직접 써줘야 했으나, JPA가 나오면서 복잡한 로직들을 전부 구현할 필요가 없어졌다.

JPA는 자바에서 지원하는 ORM이다. SQL문을 직접 작성할 필요 없이 객체 조작을 통해 DB 작업을 수행할 수 있게 하는 인터페이스이다.

JPA는 인터페이스이기 때문에 구현체가 필요한데 보통 Hibernate를 사용한다. Hibernate는 JDBC를 활용해 DB와 통신을 하는데, 순서는 다음과 같다.

```
DB ↔ JDBC ↔ Hibernate ↔ JPA ↔ Spring Data JPA (Repository) ↔ Application
```

여기서 Spring Data JPA는 우리가 직접 구현하는 Repository를 말하는데, 보통 JPA라고 하면 이쪽을 의미한다.

### Entity

데이터베이스의 테이블과 1:1로 대응되는 Java 클래스. 테이블의 행을 객체로 매핑.

#### 관련 어노테이션

**`@Entity`**: 해당 클래스가 Entity임을 선언하는 어노테이션

```java
@Entity
public class Member {
    // ...
}
```

**`@Table`**: Entity와 매핑할 테이블 정보를 지정. 웬만해서 클래스의 복수형으로 이름을 적는 것이 좋다고 한다. (이유는 단수형으로 사용하면 DB에서 이미 사용하고 있어 오류가 발생할 가능성이 있다)

```java
@Entity
@Table(name = "members")
public class Member {
    // ...
}
```

**`@Id`**: 테이블의 PK에 해당하는 필드에 사용. 기본 키의 AUTO_INCREMENT를 `@GeneratedValue`로 지정 가능하다 (MySQL에서는 IDENTITY 타입을 사용).

```java
@Entity
@Table(name = "members")
public class Member {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
}
```

**`@Column`**: 필드 속성을 지정할 수 있다. 만약 아무 조건을 설정하지 않는다면 이 어노테이션은 생략 가능하다.
1. `name` : 해당 컬럼명
2. `length` : 문자 길이 제약조건
3. `nullable` : null 허용 여부
4. `unique` : 유니크 제약조건

```java
@Entity
@Table(name = "members")
public class Member {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "member_name", length = 50, nullable = false, unique = true)
    private String name;
}
```

#### Lombok과 연계되는 어노테이션

**`@NoArgsConstructor(access = AccessLevel.PROTECTED)`**
기본 생성자를 만들어주면서 `protected`로 설정하여 외부에서의 접근을 막는다. (다른 곳에서의 직접 `new`를 통한 선언 및 초기화를 막는다. 이유는 이것은 테이블에 대응되는 목적으로 만든 것이므로. JPA가 리플렉션으로 객체를 생성할 때는 접근 제어자와 무관하게 접근 가능하다.)

**`@Getter`**
DB 테이블 내의 데이터를 읽어오기 위한 목적으로 사용된다.

```java
@Entity
@Table(name = "members")
@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class Member {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "member_name", length = 50, nullable = false)
    private String name;
}
```

### JPA 설정

JPA를 사용하기 위해선 설정이 필요하다. `resources/application.properties`(또는 `.yml`) 내에:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/jpa
spring.datasource.username=root
spring.datasource.password=12345678
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.MySQLDialect
spring.jpa.hibernate.ddl-auto=create
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

**`spring.jpa.hibernate.ddl-auto` 옵션** : 어플리케이션이 시작될 때 기존 테이블을 어떻게 처리할지

| 값 | 설명 | 사용 시점 |
|---|---|---|
| `create` | 기존 테이블 삭제 후 재생성 | 개발 초기 |
| `create-drop` | create + 어플리케이션 종료 시 테이블 삭제 | 테스트 |
| `update` | 변경분만 반영 (컬럼 추가만 가능) | 개발 중 |
| `validate` | 엔티티와 테이블 매핑 정보만 확인 | 운영 단계 |
| `none` | DDL 자동생성 사용 안 함 | 운영 단계 |

- **`spring.jpa.show-sql` 옵션** : 실행하는 모든 SQL 쿼리를 콘솔에 출력할지 여부
- **`spring.jpa.properties.hibernate.format_sql` 옵션** : 쿼리를 포매팅(보기 좋게 나열)할지 여부

## 7. 3 Layer Architecture

3개의 레이어로 소프트웨어 시스템을 나누어 관리하는 패턴.

### 장점 (관심사의 분리)

- 각 계층은 고유한 책임만 담당
- 변경 사항의 영향 범위 최소화
- 유지보수성 향상
- 코드의 가독성과 이해도 증가
- 독립적인 테스트 가능
- 재사용성 증대 — 각 계층을 독립적으로 재사용
- 모듈화된 설계
- 확장성 개선 — 특정 계층만 변경하여 기능 확장, 새로운 기술 도입 용이

### Controller Layer

일반 사용자(클라이언트)가 어플리케이션과 상호작용하는 계층. `@RestController` (혹은 `@Controller`)를 사용.

**해야 할 일**
- HTTP 요청 매핑
- 요청 파라미터 검증
- 응답 데이터 변환
- 예외 처리 및 에러 응답

**하지 말아야 할 일**
- 비즈니스 로직 처리
- 데이터베이스 직접 접근
- 복잡한 데이터 변환

### Service Layer

비즈니스 로직을 처리하는 역할의 계층. 핵심 로직이 여기에서 처리된다. `@Service`를 사용.

**해야 할 일**
- 비즈니스 규칙 구현
- 데이터 유효성 검증
- 여러 데이터 소스 조합
- 트랜잭션 경계 설정

**하지 말아야 할 일**
- HTTP 관련 처리
- 데이터베이스 쿼리 작성
- UI 관련 로직

### Repository Layer

데이터베이스와 상호작용을 담당하는 계층. 실제 DB에 데이터를 저장하거나 가져오는 역할이다.

`@Repository`라는 어노테이션이 있지만, `JpaRepository`를 상속하는 경우에는 추가로 어노테이션을 붙이지 않아도 된다.

```java
public interface UserRepository extends JpaRepository<User, Long> {
    // ...
}
```

**해야 할 일**
- CRUD 연산 구현
- 쿼리 최적화
- 데이터 매핑

**하지 말아야 할 일**
- 비즈니스 로직 처리
- HTTP 응답 생성
- 사용자 인터페이스 관련 작업

### 레이어 간 통신 규칙

상위 → 하위로 이루어져야 하고, 중간을 건너뛰어 직접 호출해서는 안 된다.

상위 → 하위 기준: **Controller → Service → Repository** 순.

## 8. DTO (Data Transfer Object)

데이터를 전달하기 위한 순수 데이터 객체. 사용자의 요청(Request)을 받을 때 스프링은 자바 코드로 변환하여 처리한다. 사용자의 요청 데이터를 자바 코드에 담아 Controller에 옮겨줄 객체를 DTO라고 부른다.

### 사용 방법

**1. 사용자가 JSON 형식으로 요청을 보낸다.**

```json
{
    "title": "범죄도시11"
}
```

**2. JSON 요청에 대응하는 DTO 클래스가 생성되어 있어야 한다.**

```java
@Getter
public class CreateMovieRequest {

    private String title;
}
```

**3. 컨트롤러에서는 `@RequestBody`와 DTO 객체 클래스를 매개변수로 두어 받은 JSON 요청을 자바 코드로 변환하여 사용한다.**

```java
@RestController
public class MovieController {

    @PostMapping("/movies")
    public void createMovie(@RequestBody CreateMovieRequest request) {
        // ...
    }
}
```

DTO는 단순하게 클라이언트와 서버 간에만 사용되는 게 아닌, 비즈니스 로직이 없는 데이터 객체이기에 계층 간 필요시 언제든 사용될 수 있다.

## 9. 트러블슈팅 — Docker에서 MySQL 띄우기

- 기존에 로컬에 MySQL을 설치하여 연결하는 방식 대신, 도커에서 설치해서 이미지로 관리하는 방식을 사용한다.
- 명령어: `docker run -d --name mysql -e MYSQL_ROOT_PASSWORD=12345678 -p 3306:3306 mysql:8.4`
- **오류 발생 원인**: 기존에 설치되어있던 MySQL을 제거하였는데, 도커에 MySQL을 설치하면서 기존에 사용하던 포트 번호(3306)와 겹치며 생긴 문제 (로컬 MySQL 서비스가 여전히 포트를 점유 중이었음).
- **해결 방법**
  - 포트를 다르게 매핑 (`-p 3307:3306`)해서 로컬 MySQL과 충돌 없이 사용
  - 또는 관리자 권한 터미널에서 로컬 MySQL 서비스 자체를 중지 (`net stop MySQL80` 등)
- Docker의 container 안에서 MySQL을 실행 및 중지가 가능하고, 설정된 포트 번호를 통해 Java에서 연결한다.
